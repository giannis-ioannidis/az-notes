# 2.4 Identity, Access, and Security

## Active Directory Services

### Microsoft Entra ID (formerly Azure Active Directory)

#### Definition
Microsoft Entra ID is Microsoft's cloud-based identity and access management service. It helps employees sign in and access resources in external resources (Microsoft 365, Azure portal, SaaS applications) and internal resources (apps on corporate network).

#### Key Characteristics
- **Cloud-Based**: Hosted and managed by Microsoft
- **Multi-Tenant**: Separate instance per organization
- **Identity Provider**: Centralized authentication and authorization
- **Global Service**: Available worldwide, no region selection needed

#### Core Features
- **Single Sign-On (SSO)**: One identity for multiple applications
- **Multi-Factor Authentication (MFA)**: Additional security beyond passwords
- **Conditional Access**: Policy-based access control
- **Device Management**: Register and manage devices
- **Application Management**: Integrate thousands of SaaS apps

#### Microsoft Entra ID vs Active Directory Domain Services

| Feature | Microsoft Entra ID | AD Domain Services |
|---------|-------------------|-------------------|
| **Type** | Cloud identity service | On-premises directory |
| **Protocol** | HTTP/HTTPS (REST APIs) | LDAP, Kerberos |
| **Structure** | Flat structure | Hierarchical (OUs, GPOs) |
| **Authentication** | Modern (OAuth, SAML, OpenID) | NTLM, Kerberos |
| **Management** | Azure Portal, PowerShell | AD Users and Computers |
| **Scope** | Global, cloud-first | On-premises, domain-joined |
| **Devices** | Cloud-joined, registered | Domain-joined |

#### Microsoft Entra ID Editions

##### Free
- **Included With**: Microsoft 365, Azure subscription
- **Features**: 
  - User and group management
  - On-premises directory sync
  - Basic reports
  - Self-service password change for cloud users
  - SSO for Azure, Microsoft 365, SaaS apps

##### Premium P1
- **Additional Features**:
  - Conditional Access
  - Dynamic groups
  - Self-service group management
  - Microsoft Identity Manager (on-premises)
  - Self-service password reset for on-premises users

##### Premium P2
- **Additional Features**:
  - Microsoft Entra ID Protection (risk-based conditional access)
  - Privileged Identity Management (PIM)
  - Access reviews
  - Entitlement management

#### Microsoft Entra Domain Services

##### Definition
Managed domain services (domain join, group policy, LDAP, Kerberos/NTLM authentication) without deploying and managing domain controllers.

##### Key Features
- **Managed Service**: Microsoft manages domain controllers
- **Compatible**: Works with traditional AD-dependent applications
- **No VPN Needed**: Integrated with Azure Virtual Networks
- **Synchronized**: One-way sync from Microsoft Entra ID

##### Use Cases
- Lift-and-shift legacy applications requiring domain join
- Applications needing LDAP or Kerberos authentication
- Azure VMs requiring group policy
- Avoid managing domain controllers in cloud

##### How It Works
```
On-Premises AD → Microsoft Entra Connect → Microsoft Entra ID → Microsoft Entra Domain Services
```

## Authentication Methods

### Overview
Authentication proves you are who you claim to be. Azure supports multiple authentication methods with varying security levels.

### Single Sign-On (SSO)

#### Definition
Allows users to sign in once and access multiple applications without re-authenticating.

#### Benefits
- **User Experience**: Sign in once, access everything
- **Security**: Fewer passwords to manage and remember
- **Productivity**: Less time spent on authentication
- **IT Efficiency**: Centralized access management

#### How It Works
```
User → Authenticates once → Microsoft Entra ID → Access Token → Multiple Apps
```

---

### Multi-Factor Authentication (MFA)

#### Definition
Security process requiring two or more verification methods to prove identity.

#### Authentication Factors

##### Something You Know
- Password
- PIN
- Security questions

##### Something You Have
- Mobile phone (SMS, app notification)
- Hardware token
- Smart card
- Security key

##### Something You Are
- Fingerprint
- Face recognition
- Retina scan
- Voice recognition

#### Microsoft Entra MFA Methods
- **Microsoft Authenticator App**: Push notification or code
- **SMS**: Text message with code
- **Voice Call**: Automated phone call
- **OATH Hardware Tokens**: Time-based one-time passwords
- **OATH Software Tokens**: Mobile app codes
- **FIDO2 Security Keys**: Physical security keys

#### Where MFA Applies
- Microsoft Entra ID sign-ins
- Azure portal access
- VPN connections
- Remote Desktop
- Application access

#### Benefits
- **Enhanced Security**: Significantly reduces account compromise
- **Compliance**: Meets regulatory requirements
- **Flexibility**: Multiple verification methods
- **User-Friendly**: Mobile app push notifications

---

### Passwordless Authentication

#### Definition
Authentication without using passwords, using more secure alternatives.

#### Passwordless Methods

##### Windows Hello for Business
- **Technology**: Biometric (face, fingerprint) or PIN
- **Scope**: Windows 10/11 devices
- **Security**: Credential tied to device
- **Use Case**: Corporate Windows devices

##### Microsoft Authenticator App
- **Technology**: Phone sign-in approval
- **Process**: Approve sign-in on registered phone
- **Security**: Biometric or PIN on phone
- **Use Case**: Mobile workforce

##### FIDO2 Security Keys
- **Technology**: Physical security key (USB, NFC, Bluetooth)
- **Standards**: FIDO Alliance standards
- **Security**: Public/private key cryptography
- **Use Case**: High-security environments, shared devices

#### Benefits of Passwordless
- **Security**: Cannot be phished or stolen like passwords
- **User Experience**: Faster, more convenient
- **Cost**: Reduce password reset help desk calls
- **Compliance**: Stronger authentication than passwords

## External Identities

### Microsoft Entra External ID

#### Definition
Capabilities for collaborating with users outside your organization, allowing external users to access your resources with their own identities.

#### Types of External Identities

##### Business-to-Business (B2B) Collaboration
- **Definition**: Invite external users (partners, vendors) to access your applications
- **User Identity**: External user keeps their own identity
- **Representation**: Appears as guest user in your directory
- **Management**: You control access to your resources

##### How B2B Works
```
Your Organization → Invites External User → User Signs In (their credentials) → 
Accesses Your Resources (as guest)
```

##### B2B Use Cases
- Partner collaboration on projects
- Vendor access to systems
- Consultant access to resources
- Cross-organization teamwork

##### Business-to-Customer (B2C)
- **Definition**: Customer-facing applications with custom identity experiences
- **User Identity**: Customers create accounts or use social identities
- **Customization**: Branded sign-in experiences
- **Scale**: Millions of users

##### B2C Use Cases
- Customer portals
- E-commerce applications
- Mobile apps with user accounts
- SaaS applications for consumers

#### External Identity Features
- **Self-Service Sign-Up**: Users can register themselves
- **Social Identities**: Sign in with Google, Facebook, etc.
- **Custom Policies**: Tailor authentication flows
- **API Connectors**: Integrate with external systems
- **Multi-Factor Authentication**: Require MFA for external users

#### Benefits
- **Security**: External users don't need separate credentials
- **Simplicity**: Users maintain their own identities
- **Control**: You manage what external users can access
- **Audit**: Track external user activities

## Conditional Access

### Definition
Conditional Access is the policy engine that enforces access controls based on signals (who, what, where, when, how) to make decisions and enforce organizational policies.

### How Conditional Access Works

#### The Policy Engine
```
Signal (User, Location, Device, App) → Policy Evaluation → Decision (Allow/Block/Require MFA)
```

### Signals (Conditions)

#### User or Group
- Specific users
- Groups
- Directory roles
- External users

#### Location
- Named locations (IP ranges)
- Trusted locations
- Country/region
- Unknown locations

#### Device
- Device platform (Windows, iOS, Android, macOS)
- Device state (compliant, hybrid joined)
- Device information

#### Application
- Specific cloud apps
- User actions
- Authentication context

#### Risk
- Sign-in risk (low, medium, high)
- User risk level
- Real-time risk detection

### Access Controls (Actions)

#### Block Access
- Completely deny access

#### Grant Access
- Allow access unconditionally

#### Grant Access with Requirements
- **Require MFA**: User must complete multi-factor authentication
- **Require Compliant Device**: Device must meet compliance policies
- **Require Hybrid Azure AD Joined**: Device joined to on-premises AD and Entra ID
- **Require Approved Client App**: Use specific mobile apps
- **Require App Protection Policy**: App must have protection policy
- **Require Password Change**: Force password change

#### Session Controls
- **Use app enforced restrictions**: Limit functionality in apps
- **Use Conditional Access App Control**: Monitor and control sessions
- **Sign-in frequency**: Require re-authentication after time period
- **Persistent browser session**: Stay signed in

### Common Conditional Access Policies

#### Policy 1: Require MFA for Administrators
```
IF: User is in administrator role
AND: Accessing Azure Portal
THEN: Require multi-factor authentication
```

#### Policy 2: Block Access from Untrusted Locations
```
IF: Access from unknown location
AND: Accessing sensitive applications
THEN: Block access
```

#### Policy 3: Require Compliant Device
```
IF: User accessing Microsoft 365
AND: Device is not compliant
THEN: Block access
```

#### Policy 4: Require MFA for Risky Sign-ins
```
IF: Sign-in risk is medium or high
THEN: Require multi-factor authentication
```

### Benefits
- **Adaptive Security**: Context-aware access decisions
- **Zero Trust**: Verify explicitly, every time
- **Productivity**: Seamless access for trusted scenarios
- **Compliance**: Enforce organizational policies
- **Risk-Based**: Respond to real-time threats

### Best Practices
- Start with report-only mode (test before enforcing)
- Exclude emergency access accounts
- Deploy in stages (pilot → production)
- Use multiple policies for different scenarios
- Monitor policy effectiveness regularly

## Role-Based Access Control (RBAC)

### Definition
Authorization system that provides fine-grained access management to Azure resources. Controls what users can do with Azure resources.

### Key Concepts

#### Security Principal (Who)
- **User**: Individual person
- **Group**: Collection of users
- **Service Principal**: Application or service identity
- **Managed Identity**: Automatically managed identity for Azure resources

#### Role Definition (What)
- Collection of permissions
- Defines allowed operations
- Can be built-in or custom

#### Scope (Where)
- **Management Group**: Multiple subscriptions
- **Subscription**: Billing boundary
- **Resource Group**: Container for related resources
- **Resource**: Individual resource

### Role Assignment
```
Security Principal + Role Definition + Scope = Role Assignment
(Who)              (What they can do)   (Where)
```

### Built-in Roles

#### Fundamental Roles

##### Owner
- **Permissions**: Full access to all resources
- **Special**: Can grant access to others
- **Use Case**: Subscription administrators

##### Contributor
- **Permissions**: Create and manage all resources
- **Cannot**: Grant access to others
- **Use Case**: Developers, resource managers

##### Reader
- **Permissions**: View all resources
- **Cannot**: Make any changes
- **Use Case**: Auditors, read-only access

##### User Access Administrator
- **Permissions**: Manage user access to Azure resources
- **Cannot**: Manage resources themselves
- **Use Case**: Access management team

#### Service-Specific Roles

##### Virtual Machine Contributor
- Create and manage VMs
- Cannot manage network or storage accounts

##### Storage Blob Data Contributor
- Read, write, delete blob containers and data
- Cannot manage storage account itself

##### SQL DB Contributor
- Manage SQL databases
- Cannot manage security policies or SQL servers

##### Network Contributor
- Manage network resources
- Cannot access other resources

### Custom Roles

#### When to Create Custom Roles
- Built-in roles too permissive
- Need specific combination of permissions
- Least privilege principle
- Organizational requirements

#### Custom Role Structure
```json
{
  "Name": "Custom Role Name",
  "Description": "Description",
  "Actions": [
    "Microsoft.Compute/*/read",
    "Microsoft.Storage/*/read"
  ],
  "NotActions": [
    "Microsoft.Compute/virtualMachines/delete"
  ],
  "AssignableScopes": [
    "/subscriptions/{subscription-id}"
  ]
}
```

### RBAC Scope Hierarchy

```
Management Group (broadest scope)
  ↓ inherits
Subscription
  ↓ inherits
Resource Group
  ↓ inherits
Resource (narrowest scope)
```

#### Inheritance Rules
- Permissions granted at parent scope apply to child scopes
- More restrictive child permissions don't override parent
- Deny assignments take precedence over allow

### Best Practices
- **Least Privilege**: Grant minimum necessary permissions
- **Use Groups**: Assign roles to groups, not individuals
- **Custom Roles**: Create when built-in roles too broad
- **Regular Review**: Audit role assignments periodically
- **Separate Duties**: Different roles for different responsibilities
- **Document**: Maintain documentation of role assignments

## Zero Trust Model

### Definition
Security model that assumes breach and verifies each request as though it originated from an uncontrolled network. "Never trust, always verify."

### Core Principles

#### Verify Explicitly
- Always authenticate and authorize
- Use all available data points (identity, location, device, service, data)
- Make intelligent access decisions

#### Use Least Privilege Access
- Limit user access with Just-In-Time and Just-Enough-Access (JIT/JEA)
- Risk-based adaptive policies
- Data protection to prevent accidental exposure

#### Assume Breach
- Minimize blast radius for breaches
- Segment access by network, user, devices, applications
- Use encryption to protect data
- Use analytics to detect threats and improve defenses

### Zero Trust Pillars

#### Identities
- **Verify**: Strong authentication (MFA, passwordless)
- **Secure**: Risk-based access policies
- **Monitor**: Sign-in behavior and anomalies

#### Devices
- **Monitor**: Device health and compliance
- **Control**: Access based on device state
- **Update**: Keep devices patched and secure

#### Applications
- **Discover**: Shadow IT and unmanaged apps
- **Control**: Appropriate in-app permissions
- **Monitor**: Unusual application behavior

#### Data
- **Classify**: Know your sensitive data
- **Encrypt**: Protect data at rest and in transit
- **Control**: Prevent data leakage

#### Infrastructure
- **Assess**: Security posture
- **Detect**: Attacks and anomalies
- **Block**: Threats automatically

#### Networks
- **Segment**: Isolate and control access
- **Monitor**: All network traffic
- **Encrypt**: All communications

### Zero Trust vs Traditional Security

| Aspect | Traditional (Castle-and-Moat) | Zero Trust |
|--------|------------------------------|------------|
| **Trust Model** | Trust inside perimeter | Never trust, always verify |
| **Network** | Flat internal network | Micro-segmentation |
| **Access** | Broad network access | Least privilege, JIT |
| **Authentication** | Once at perimeter | Continuous verification |
| **Monitoring** | Perimeter focus | All traffic monitored |

### Implementing Zero Trust

#### Phase 1: Visualize
- Understand resources, data flows, dependencies
- Identify sensitive data and critical assets

#### Phase 2: Mitigate
- Implement MFA and conditional access
- Apply least privilege access
- Segment networks

#### Phase 3: Optimize
- Automate security responses
- Use AI/ML for threat detection
- Continuous improvement

### Microsoft Zero Trust Capabilities
- **Microsoft Entra ID**: Identity verification
- **Conditional Access**: Policy-based access
- **Microsoft Defender for Cloud**: Threat protection
- **Azure Firewall**: Network security
- **Microsoft Purview**: Data governance
- **Microsoft Sentinel**: SIEM/SOAR

## Defense-in-Depth

### Definition
Security strategy that uses multiple layers of protection to defend against attacks. If one layer fails, additional layers provide continued protection.

### The Layers

#### Layer 1: Physical Security
- **What**: Physical building and datacenter security
- **Controls**:
  - Biometric access controls
  - Security personnel
  - Surveillance cameras
  - Secure facilities
- **Azure**: Microsoft manages physical security of datacenters

#### Layer 2: Identity & Access
- **What**: Control who can access resources
- **Controls**:
  - Multi-factor authentication
  - Conditional access policies
  - Role-based access control
  - Azure AD authentication
- **Principle**: Verify identity before granting access

#### Layer 3: Perimeter
- **What**: Network edge protection
- **Controls**:
  - DDoS protection
  - Perimeter firewalls
  - Azure Firewall
  - Azure Front Door
- **Purpose**: Filter large-scale attacks before they reach resources

#### Layer 4: Network
- **What**: Network segmentation and traffic control
- **Controls**:
  - Network segmentation (subnets)
  - Network Security Groups (NSGs)
  - Service endpoints
  - Private endpoints
  - Virtual network peering rules
- **Principle**: Limit communication between resources

#### Layer 5: Compute
- **What**: Secure virtual machines and compute resources
- **Controls**:
  - Secure VM access
  - Patch management
  - Endpoint protection
  - Application whitelisting
  - VM disk encryption
- **Azure**: Azure Security Center recommendations

#### Layer 6: Application
- **What**: Secure application development and deployment
- **Controls**:
  - Secure development lifecycle
  - Input validation
  - SQL injection prevention
  - XSS protection
  - API security
- **Azure**: App Service security features

#### Layer 7: Data
- **What**: Protect the actual data (innermost layer)
- **Controls**:
  - Encryption at rest
  - Encryption in transit
  - Access controls
  - Key management (Azure Key Vault)
  - Database security
- **Principle**: Data is ultimate target, most critical protection

```

│  Physical Security (Datacenter)     │ Layer 1
│  ┌───────────────────────────────┐  │

│  │  │  ┌───────────────────┐  │  │  │
│  │  │  │  Network (NSG)    │  │  │  │ Layer 4
│  │  │  │  ┌─────────────┐  │  │  │  │
│  │  │  │  │  Compute    │  │  │  │  │ Layer 5
│  │  │  │  │  ┌───────┐  │  │  │  │  │
│  │  │  │  │  │  App  │  │  │  │  │  │ Layer 6
│  │  │  │  │  │ ┌───┐ │  │  │  │  │  │
│  │  │  │  │  │ │Data│ │  │  │  │  │  │ Layer 7
│  │  │  │  │  │ └───┘ │  │  │  │  │  │
```

### Key Principles
- **Layered Security**: Multiple independent layers
- **Redundancy**: If one layer compromised, others protect
- **Slow Down Attackers**: More time to detect and respond
- **Defense Variety**: Different security mechanisms
- **No Single Point of Failure**: Distributed defense

### Azure Defense-in-Depth Tools

| Layer | Azure Services |
|-------|----------------|
| **Physical** | Microsoft-managed datacenters |
| **Identity** | Microsoft Entra ID, MFA, Conditional Access |
| **Perimeter** | Azure DDoS Protection, Azure Firewall |

| **Compute** | Microsoft Defender for Cloud, VM updates |
| **Application** | App Service security, API Management |
| **Data** | Azure Storage encryption, Key Vault, SQL TDE |

## Microsoft Defender for Cloud

### Definition
Unified infrastructure security management system that strengthens security posture of datacenters and provides advanced threat protection across hybrid workloads.

### Key Capabilities

#### Cloud Security Posture Management (CSPM)
- **Assess**: Continuous assessment of security configuration
- **Recommendations**: Actionable security recommendations
- **Secure Score**: Numerical score representing security posture
- **Compliance**: Built-in compliance standards
- **Inventory**: Complete asset inventory

#### Cloud Workload Protection (CWP)
- **Threat Protection**: Advanced threat detection
- **Alerts**: Security alerts for suspicious activities
- **Incident Response**: Investigation and response tools
- **Integration**: SIEM integration (Microsoft Sentinel)

### Defender for Cloud Features

#### Secure Score

##### What It Is
- Measurement of security posture (0-100%)
- Higher score = better security
- Based on security recommendations

##### How It Works
```
Total Points Earned / Total Points Available × 100 = Secure Score
```

##### Benefits
- Track security improvements over time
- Compare with benchmarks
- Prioritize security efforts
- Demonstrate compliance progress

#### Security Recommendations
- Prioritized list of security improvements
- Impact on secure score shown
- Step-by-step remediation guidance
- Automated remediation available for some

#### Security Alerts
- Real-time threat detection
- Machine learning-based anomaly detection
- Integration with Microsoft Threat Intelligence
- Severity levels (High, Medium, Low, Informational)

User Requests Access → Approval (automatic/manual) →

#### Benefits
- Prevent unauthorized access
- Reduce exposure to attacks
- Audit access requests
- Compliance with least privilege
