# 2.4 Azure Identity, Access & Security

## Azure Active Directory (Azure AD) / Microsoft Entra ID

### Definition
Microsoft's cloud-based identity and access management service that helps employees sign in and access resources.

### Key Capabilities
- **Identity Management**: Manage users and groups
- **Authentication**: Verify user identities
- **Authorization**: Control access to resources
- **Single Sign-On (SSO)**: Access multiple applications with one login
- **Multi-Factor Authentication**: Additional security layers

### Azure AD vs On-Premises Active Directory

| Feature | On-Premises AD | Azure AD |
|---------|----------------|----------|
| **Protocol** | LDAP, Kerberos | HTTP, HTTPS, REST APIs |
| **Structure** | Forests, domains, OUs | Flat structure with tenants |
| **Authentication** | Kerberos, NTLM | SAML, OAuth, OpenID Connect |
| **Management** | Group Policy | Conditional Access policies |
| **Scope** | On-premises resources | Cloud and on-premises |

### Azure AD Editions

#### Azure AD Free
- **Users**: Up to 500,000 objects
- **Features**: Basic identity management, SSO
- **MFA**: Limited to administrators
- **Included**: With Azure subscription

#### Azure AD Premium P1
- **Hybrid Identity**: On-premises integration
- **Conditional Access**: Basic conditional access
- **Self-Service**: Password reset, group management
- **Advanced Reports**: Sign-in and usage reports

#### Azure AD Premium P2
- **Identity Protection**: Risk-based policies
- **Privileged Identity Management**: Just-in-time access
- **Access Reviews**: Regular access certifications
- **Advanced Protection**: Identity governance features

### Azure AD Concepts

#### Tenant
- **Definition**: Dedicated instance of Azure AD
- **Representation**: Represents an organization
- **Isolation**: Separate from other tenants
- **Default Domain**: tenant.onmicrosoft.com

#### Users
- **Types**: Cloud-only, synchronized, guest users
- **Attributes**: Name, email, job title, location
- **Authentication**: Username/password, MFA, passwordless
- **Licenses**: Assign services and features

#### Groups
- **Security Groups**: Manage access to resources
- **Microsoft 365 Groups**: Collaboration features
- **Distribution Groups**: Email distribution lists
- **Dynamic Groups**: Membership based on attributes

## Authentication vs Authorization

### Authentication
- **Definition**: Process of verifying identity ("Who are you?")
- **Methods**: Password, MFA, biometrics, certificates
- **Goal**: Confirm user is who they claim to be
- **Examples**: Username/password, fingerprint, smart card

### Authorization
- **Definition**: Process of granting access ("What can you do?")
- **Methods**: Role assignments, permissions, policies
- **Goal**: Determine what resources user can access
- **Examples**: Read-only access, admin privileges, resource-specific permissions

### Authentication Flow
1. User presents credentials
2. System verifies credentials
3. System creates security token
4. Token used for authorization decisions

## Multi-Factor Authentication (MFA)

### Definition
Security process requiring users to provide two or more verification factors to gain access to resources.

### Authentication Factors

#### Something You Know
- **Passwords**: Traditional text passwords
- **PINs**: Personal identification numbers
- **Security Questions**: Predetermined questions and answers

#### Something You Have
- **Mobile Phone**: SMS codes, phone calls
- **Hardware Tokens**: Physical security keys
- **Smart Cards**: Certificate-based authentication
- **Authenticator Apps**: Microsoft Authenticator, Google Authenticator

#### Something You Are
- **Biometrics**: Fingerprints, facial recognition
- **Voice Recognition**: Voice patterns
- **Retina Scans**: Eye-based authentication

### Azure AD MFA Features
- **Conditional Access**: MFA based on risk assessment
- **Remember Devices**: Trusted device registration
- **App Passwords**: For legacy applications
- **Fraud Alerts**: Report fraudulent authentication attempts

### Benefits
- **Enhanced Security**: Significantly reduces account compromise
- **Compliance**: Meets regulatory requirements
- **User Trust**: Increases confidence in security
- **Reduced Risk**: Minimizes impact of password breaches

## Passwordless Authentication

### Definition
Authentication methods that don't require traditional passwords, using more secure and user-friendly alternatives.

### Passwordless Options

#### Windows Hello for Business
- **Biometrics**: Facial recognition, fingerprint
- **PIN**: Device-specific PIN
- **Security**: Key-based authentication
- **Integration**: Works with Azure AD

#### Microsoft Authenticator App
- **Push Notifications**: Approve sign-in requests
- **Number Matching**: Enter displayed number
- **Biometrics**: Use device biometrics
- **Offline**: Works without internet connection

#### FIDO2 Security Keys
- **Physical Keys**: USB, NFC, Bluetooth devices
- **Standards**: FIDO2/WebAuthn compliant
- **Phishing Resistant**: Cannot be replayed
- **Cross-platform**: Works across devices and browsers

### Benefits
- **Security**: More secure than passwords
- **User Experience**: Faster and more convenient
- **Cost Reduction**: Reduces help desk calls
- **Phishing Protection**: Resistant to phishing attacks

## Conditional Access

### Definition
Tool that Azure AD uses to bring signals together, make decisions, and enforce organizational policies.

### Signal Sources
- **User/Group**: Who is accessing
- **Location**: Where access is coming from
- **Device**: What device is being used
- **Application**: What app is being accessed
- **Risk Detection**: Real-time risk assessment

### Decision Engine
- **Grant Access**: Allow access with/without controls
- **Block Access**: Deny access completely
- **Require Controls**: MFA, compliant device, approved app

### Common Policies

#### Require MFA for Administrators
- **Users**: Admin roles
- **Conditions**: All cloud apps
- **Controls**: Require MFA

#### Block Access from Untrusted Locations
- **Users**: All users
- **Conditions**: Access from risky locations
- **Controls**: Block access

#### Require Compliant Devices
- **Users**: All users
- **Conditions**: Office 365 apps
- **Controls**: Require device compliance

### Benefits
- **Zero Trust**: Verify explicitly before granting access
- **Adaptive**: Responds to real-time conditions
- **Comprehensive**: Covers users, devices, apps, locations
- **Automated**: Reduces manual intervention

## Role-Based Access Control (RBAC)

### Definition
Authorization system that provides fine-grained access management of Azure resources based on roles assigned to users, groups, or applications.

### RBAC Components

#### Security Principal
- **User**: Individual person with Azure AD account
- **Group**: Set of users in Azure AD
- **Service Principal**: Security identity for applications/services
- **Managed Identity**: Azure-managed service principal

#### Role Definition
- **Built-in Roles**: Predefined roles by Microsoft
- **Custom Roles**: User-defined roles with specific permissions
- **Actions**: Operations that can be performed
- **NotActions**: Operations explicitly denied

#### Scope
- **Management Group**: Collection of subscriptions
- **Subscription**: Billing boundary and access control
- **Resource Group**: Container for related resources
- **Resource**: Individual Azure service instance

### Built-in Roles

#### Owner
- **Permissions**: Full access including access management
- **Use Cases**: Subscription administrators
- **Inheritance**: Permissions inherited by child scopes

#### Contributor
- **Permissions**: Create and manage resources (no access management)
- **Use Cases**: Developers, system administrators
- **Limitations**: Cannot grant access to others

#### Reader
- **Permissions**: View resources only
- **Use Cases**: Auditors, monitoring personnel
- **Scope**: Read-only access to all resource types

#### User Access Administrator
- **Permissions**: Manage user access to Azure resources
- **Use Cases**: Identity administrators
- **Scope**: Limited to access management only

### Role Assignment Process
1. **Identify Security Principal**: Who needs access
2. **Select Role Definition**: What permissions needed
3. **Choose Scope**: Where permissions apply
4. **Create Assignment**: Link principal, role, and scope

### Best Practices
- **Principle of Least Privilege**: Grant minimum required permissions
- **Use Groups**: Assign roles to groups, not individuals
- **Regular Reviews**: Periodically review and update assignments
- **Custom Roles**: Create specific roles for unique requirements

## Azure Security Services

### Microsoft Defender for Cloud

#### Definition
Cloud Security Posture Management (CSPM) and Cloud Workload Protection Platform (CWPP) for Azure, hybrid, and multi-cloud environments.

#### Key Features
- **Security Posture**: Continuous assessment and recommendations
- **Threat Protection**: Advanced threat detection and response
- **Compliance**: Regulatory compliance monitoring
- **Secure Score**: Measurement of security posture

#### Defender Plans
- **Free**: Basic security policies and recommendations
- **Enhanced Security**: Advanced threat protection features
- **Workload Specific**: Protection for VMs, databases, containers, etc.

#### Benefits
- **Unified Dashboard**: Single pane of glass for security
- **Automated Response**: Automatic remediation capabilities
- **Integration**: Works with existing security tools
- **Multi-cloud**: Protects AWS and GCP resources

### Azure Key Vault

#### Definition
Cloud service for securely storing and accessing secrets, keys, and certificates.

#### Key Vault Objects

##### Secrets
- **Definition**: Small pieces of sensitive data
- **Examples**: Passwords, connection strings, API keys
- **Versioning**: Multiple versions maintained
- **Access Control**: Fine-grained permissions

##### Keys
- **Types**: RSA, Elliptic Curve keys
- **Protection**: Software or HSM-protected
- **Operations**: Encrypt, decrypt, sign, verify
- **Import/Generate**: Create or import existing keys

##### Certificates
- **SSL/TLS**: Web server certificates
- **Code Signing**: Application signing certificates
- **Management**: Automatic renewal and lifecycle
- **Integration**: Works with Azure services

#### Security Features
- **Hardware Security Modules**: FIPS 140-2 Level 2 validated
- **Access Policies**: Control who can access what
- **Logging**: Comprehensive audit logging
- **Network Isolation**: VNet integration and private endpoints

#### Benefits
- **Centralized Management**: Single location for secrets
- **Application Integration**: Easy integration with applications
- **Compliance**: Meets various compliance standards
- **Cost Effective**: Pay-per-operation pricing

### Azure Information Protection (AIP)

#### Definition
Cloud-based solution that helps organizations discover, classify, and protect documents and emails by applying labels.

#### Key Features
- **Classification**: Automatic and manual classification
- **Labeling**: Visual labels and metadata
- **Protection**: Encryption and access controls
- **Tracking**: Monitor document usage

#### Label Types
- **Public**: No business impact if shared
- **Internal**: Business impact if shared externally
- **Confidential**: Serious business impact if shared
- **Highly Confidential**: Severe business impact

#### Benefits
- **Data Discovery**: Find sensitive data across organization
- **Consistent Classification**: Standardized labeling
- **Persistent Protection**: Protection travels with data
- **User Awareness**: Visual cues for data sensitivity

## Zero Trust Security Model

### Definition
Security strategy that assumes no implicit trust and continuously validates every transaction.

### Core Principles

#### Verify Explicitly
- **Always Authenticate**: Never assume trust
- **Multiple Factors**: Use all available data points
- **Real-time Assessment**: Continuous verification

#### Use Least Privilege Access
- **Just-in-Time**: Access when needed
- **Just-Enough**: Minimum required permissions
- **Risk-based**: Adaptive based on risk assessment

#### Assume Breach
- **Minimize Blast Radius**: Limit impact of breaches
- **Verify End-to-End**: Encrypt and verify everything
- **Analytics**: Use data for threat detection

### Implementation Areas

#### Identity
- **Strong Authentication**: MFA, passwordless
- **Risk Assessment**: Real-time risk evaluation
- **Privileged Access**: Just-in-time administration

#### Devices
- **Device Compliance**: Ensure device security
- **Device Management**: Control device access
- **Device Trust**: Verify device integrity

#### Applications
- **App Discovery**: Identify all applications
- **App Permissions**: Control app access
- **App Monitoring**: Monitor app usage

#### Data
- **Data Classification**: Identify sensitive data
- **Data Protection**: Encrypt and control access
- **Data Governance**: Manage data lifecycle

#### Infrastructure
- **Network Segmentation**: Limit lateral movement
- **Infrastructure Hardening**: Secure configurations
- **Monitoring**: Continuous infrastructure monitoring

#### Networks
- **Network Isolation**: Segment network traffic
- **Encryption**: Encrypt all network traffic
- **Monitoring**: Real-time network analysis

### Azure Zero Trust Services
- **Azure AD Conditional Access**: Risk-based access
- **Microsoft Intune**: Device management and compliance
- **Azure Information Protection**: Data classification and protection
- **Microsoft Defender for Cloud**: Infrastructure security
- **Azure Sentinel**: Security information and event management

## Defense in Depth

### Definition
Layered security strategy that uses multiple security measures to protect information and systems.

### Security Layers

#### Physical Security
- **Datacenter Protection**: Biometric access, surveillance
- **Hardware Security**: Tamper-resistant hardware
- **Environmental Controls**: Fire suppression, climate control

#### Identity and Access
- **Authentication**: Verify user identity
- **Authorization**: Control resource access
- **Privileged Access**: Manage administrative access

#### Perimeter
- **Firewalls**: Filter network traffic
- **DDoS Protection**: Mitigate distributed attacks
- **VPN**: Secure remote access

#### Network
- **Network Segmentation**: Isolate network traffic
- **Network Monitoring**: Detect suspicious activity
- **Network Access Control**: Control device access

#### Compute
- **Endpoint Protection**: Antimalware, host firewalls
- **System Hardening**: Secure configurations
- **Patch Management**: Keep systems updated

#### Application
- **Secure Development**: Secure coding practices
- **Application Firewalls**: Protect web applications
- **API Security**: Secure application interfaces

#### Data
- **Data Classification**: Identify sensitive data
- **Encryption**: Protect data at rest and in transit
- **Data Loss Prevention**: Prevent data exfiltration

### Benefits
- **Multiple Barriers**: Attackers must breach multiple layers
- **Redundancy**: Backup protection if one layer fails
- **Comprehensive**: Protects against various attack vectors
- **Flexibility**: Can adapt to different threat scenarios
