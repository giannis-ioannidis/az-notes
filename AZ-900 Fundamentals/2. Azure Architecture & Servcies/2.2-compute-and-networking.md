# 2.2 Azure Compute and Networking Services

## Azure Compute Services

### Virtual Machines (VMs)

#### Definition
Azure Virtual Machines provide on-demand, scalable computing resources with the flexibility of virtualization without having to buy and maintain physical hardware.

#### Key Characteristics
- **IaaS Service**: Full control over the operating system
- **Multiple OS Support**: Windows Server, Linux distributions
- **Customizable**: Configure CPU, memory, storage, networking
- **Lift-and-Shift**: Easy migration from on-premises

#### VM Components
- **Virtual Machine**: The compute resource itself
- **Managed Disks**: Storage for OS and data
- **Virtual Network**: Network connectivity
- **Network Security Group**: Firewall rules
- **Public IP Address**: Internet connectivity (optional)

#### VM Sizes and Series
- **General Purpose** (B, D series): Balanced CPU-to-memory, dev/test
- **Compute Optimized** (F series): High CPU-to-memory, web servers
- **Memory Optimized** (E, M series): High memory-to-CPU, databases
- **Storage Optimized** (L series): High disk throughput
- **GPU** (N series): Graphics rendering, machine learning

#### Availability Options
- **Availability Sets**: Spread VMs across fault/update domains (99.95% SLA)
- **Availability Zones**: Physical separation within region (99.99% SLA)
- **Virtual Machine Scale Sets**: Auto-scaling groups of VMs

#### Use Cases
- Hosting web applications and APIs
- Running custom applications requiring specific OS configurations
- Development and test environments
- Disaster recovery scenarios
- Legacy application migration (lift-and-shift)

#### Benefits
- Complete control over the environment
- Support for custom software and configurations
- Flexible scaling options
- Pay only for what you use

#### Considerations
- You manage the operating system and applications
- Requires patching and maintenance
- Higher management overhead than PaaS options

### Azure Virtual Desktop (AVD)

#### Definition
Desktop and application virtualization service that runs in the cloud, providing users with remote access to Windows desktops and applications.

#### Key Features
- **Windows 10/11 Multi-Session**: Multiple users on single VM
- **Microsoft 365 Integration**: Optimized for Microsoft 365 Apps
- **FSLogix Profile Containers**: User profile management
- **Centralized Management**: Azure Portal or Windows Admin Center

#### Components
- **Host Pools**: Collections of VMs serving desktops/apps
- **Application Groups**: Published desktops or RemoteApps
- **Workspaces**: User-facing portal for accessing resources
- **Session Hosts**: VMs running the desktops/applications

#### Deployment Options
- **Personal Desktops**: Dedicated VM per user
- **Pooled Desktops**: Shared VMs, non-persistent sessions
- **RemoteApp**: Stream individual applications

#### Use Cases
- Remote workforce enablement
- Bring Your Own Device (BYOD) scenarios
- Short-term and seasonal workers
- Access to legacy applications
- Secure access to sensitive data

#### Benefits
- Reduced infrastructure costs (no VDI infrastructure to maintain)
- Improved security (data stays in Azure)
- Flexible scaling based on demand
- Optimized Microsoft 365 experience
- User personalization with FSLogix

#### Licensing
- Requires Windows or Microsoft 365 license
- Per-user licensing model
- Azure consumption costs for VMs and storage

### Containers

#### Definition
Lightweight, portable, and self-sufficient units that package application code with all dependencies, running consistently across different computing environments.

#### Container vs Virtual Machines
| Aspect | Containers | Virtual Machines |
|--------|-----------|------------------|
| **Size** | Megabytes | Gigabytes |
| **Startup** | Seconds | Minutes |
| **OS** | Shares host OS | Separate OS per VM |
| **Isolation** | Process-level | Hardware-level |
| **Portability** | Highly portable | Less portable |

#### Azure Container Services

##### Azure Container Instances (ACI)
- **Definition**: Fastest way to run containers without managing VMs
- **Use Case**: Simple containerized applications, batch jobs
- **Billing**: Per-second billing
- **Features**: Quick startup, no orchestration

##### Azure Kubernetes Service (AKS)
- **Definition**: Managed Kubernetes orchestration service
- **Use Case**: Complex microservices, enterprise applications
- **Features**: 
  - Automatic scaling
  - Self-healing
  - Load balancing
  - Rolling updates
  - Service discovery
- **Management**: Azure manages control plane (free)

##### Azure Container Apps
- **Definition**: Serverless container platform built on Kubernetes
- **Use Case**: Microservices, event-driven applications
- **Features**:
  - Auto-scaling (including scale-to-zero)
  - Built-in service discovery
  - Dapr integration
  - Simplified deployment

#### Container Benefits
- **Consistency**: Same environment from dev to production
- **Efficiency**: Better resource utilization than VMs
- **Portability**: Run anywhere (on-premises, cloud, hybrid)
- **Fast Deployment**: Start in seconds
- **Microservices**: Ideal for microservices architecture

#### Use Cases
- Microservices architectures
- CI/CD pipelines
- Batch processing jobs
- Machine learning model deployment
- API services

### Azure Functions

#### Definition
Serverless compute service that runs event-triggered code without managing infrastructure. You write code that responds to events, and Azure handles the execution.

#### Key Characteristics
- **Event-Driven**: Executes in response to triggers
- **Serverless**: No infrastructure management
- **Automatic Scaling**: Scales automatically based on demand
- **Pay-Per-Execution**: Pay only when functions run
- **Stateless**: Each execution is independent (by default)

#### Trigger Types
- **HTTP Trigger**: API endpoints, webhooks
- **Timer Trigger**: Scheduled tasks (cron jobs)
- **Blob Trigger**: File uploads to storage
- **Queue Trigger**: Messages in queue
- **Event Grid Trigger**: Events from Azure services
- **Cosmos DB Trigger**: Database changes
- **Service Bus Trigger**: Messages from Service Bus

#### Hosting Plans
- **Consumption Plan**: True serverless, pay per execution
- **Premium Plan**: Pre-warmed instances, longer execution time
- **Dedicated Plan**: Run on App Service Plan (predictable billing)

#### Supported Languages
- C#, Java, JavaScript/TypeScript, Python, PowerShell

#### Use Cases
- API backends
- Data processing pipelines
- Scheduled tasks (backups, cleanup)
- File processing (image resizing, video transcoding)
- IoT data processing
- Webhook handlers
- Integration glue between services

#### Benefits
- **No Infrastructure Management**: Focus on code only
- **Automatic Scaling**: Handle 1 to 1000s of requests
- **Cost-Effective**: Pay only for execution time
- **Fast Development**: Quick deployment and iteration
- **Event-Driven Architecture**: Natural fit for modern apps

#### Limitations
- **Execution Time Limits**: 5-10 minutes (Consumption plan)
- **Cold Start**: Initial latency if not pre-warmed
- **Stateless**: Need external storage for state management

### App Hosting Options

#### Azure App Service

##### Definition
Fully managed platform (PaaS) for building, deploying, and scaling web apps, mobile backends, and RESTful APIs.

##### Key Features
- **Multiple Languages**: .NET, Java, Node.js, Python, PHP
- **Built-in CI/CD**: GitHub, Azure DevOps, Bitbucket
- **Auto-Scaling**: Scale up/out based on rules
- **Deployment Slots**: Blue-green deployments, staging
- **Custom Domains**: Bring your own domain
- **SSL Certificates**: Free managed certificates

##### App Service Types
- **Web Apps**: Host websites and web applications
- **API Apps**: RESTful API backends
- **Mobile Apps**: Mobile backend services
- **Function Apps**: Serverless functions

##### App Service Plans
- **Free/Shared**: For dev/test, limited features
- **Basic**: Small production workloads
- **Standard**: Production workloads, deployment slots
- **Premium**: Enhanced performance, more features
- **Isolated**: Dedicated environment, maximum scale

##### Use Cases
- Web applications and websites
- RESTful APIs
- Mobile app backends
- Microservices

##### Benefits
- Fully managed platform
- Built-in DevOps capabilities
- High availability and auto-scaling
- Enterprise-grade security and compliance

#### Comparison of Hosting Options

| Service | Best For | Management | Scaling | Cost Model |
|---------|----------|------------|---------|-----------|
| **VMs** | Full control, custom software | You manage | Manual/VMSS | Pay for VM uptime |
| **App Service** | Web apps, APIs | Managed | Auto-scale | App Service Plan |
| **Containers (AKS)** | Microservices, complex apps | Moderate | Orchestrated | Per node |
| **Container Apps** | Microservices, serverless | Managed | Auto (scale-to-zero) | Per usage |
| **Functions** | Event-driven, small tasks | Fully managed | Auto | Per execution |

## Azure Networking Services

### Virtual Networking (VNet)

#### Definition
Fundamental building block for private networks in Azure. VNets enable Azure resources to securely communicate with each other, the internet, and on-premises networks.

#### Key Concepts

##### Address Space
- **Private IP ranges**: Define using CIDR notation
- **Example**: 10.0.0.0/16 provides 65,536 addresses
- **Non-overlapping**: Must not overlap with other VNets or on-premises

##### Subnets
- **Subdivision of VNet**: Organize and secure resources
- **Example**: 10.0.1.0/24 (256 addresses)
- **Purpose-based**: Web tier, app tier, database tier
- **Reserved IPs**: Azure reserves 5 IPs per subnet

##### Network Security Groups (NSG)
- **Definition**: Virtual firewall for controlling traffic
- **Rules**: Allow/deny based on source, destination, port, protocol
- **Priority**: Lower number = higher priority (100-4096)
- **Scope**: Apply to subnet or individual network interface

##### Network Interface Card (NIC)
- **Definition**: Connects VM to virtual network
- **IP Configuration**: Private IP (required), Public IP (optional)
- **Multiple NICs**: VMs can have multiple network interfaces

#### VNet Features

##### VNet Peering
- **Definition**: Connect VNets to enable direct communication
- **Regional**: VNets in same region
- **Global**: VNets across different regions
- **Benefits**: Low latency, high bandwidth, private communication
- **No Downtime**: Peering configured without interruption

##### Service Endpoints
- **Definition**: Extend VNet to Azure services
- **Purpose**: Secure Azure service resources to VNet
- **Example**: Allow only VNet to access storage account
- **Benefits**: Improved security, optimal routing

##### Private Link
- **Definition**: Access Azure services over private endpoint
- **Private Endpoint**: Creates private IP in your VNet
- **Benefits**: No public internet exposure, keeps traffic on Azure network

#### Use Cases
- Isolate and segment Azure resources
- Connect cloud and on-premises infrastructure
- Filter and route network traffic
- Connect multiple Azure resources securely

#### Benefits
- **Isolation and Segmentation**: Logical isolation of resources
- **Internet Connectivity**: Control inbound/outbound access
- **Integration**: Connect on-premises and cloud networks
- **Traffic Filtering**: Control with NSGs and firewalls
- **Traffic Routing**: Custom routes with route tables

### Azure DNS

#### Definition
Hosting service for DNS domains that provides name resolution using Microsoft Azure infrastructure.

#### Key Features
- **High Availability**: 100% availability SLA
- **Global Presence**: Anycast network across Azure regions
- **Fast Performance**: Responds to DNS queries quickly
- **Security**: Role-based access control, activity logs
- **Integration**: Works with other Azure services

#### DNS Zone Types

##### Public DNS Zones
- **Purpose**: Host domains accessible from internet
- **Use Case**: www.contoso.com, api.contoso.com
- **DNS Records**: A, AAAA, CNAME, MX, TXT, etc.

##### Private DNS Zones
- **Purpose**: Name resolution within VNets
- **Use Case**: Internal resources, VM name resolution
- **Auto-Registration**: Automatically register VM DNS names
- **Benefits**: No need for custom DNS solution

#### Common DNS Record Types
- **A Record**: Maps domain to IPv4 address
- **AAAA Record**: Maps domain to IPv6 address
- **CNAME Record**: Alias to another domain name
- **MX Record**: Mail server records
- **TXT Record**: Text information (SPF, verification)
- **NS Record**: Name server records
- **SOA Record**: Start of Authority

#### DNS Features

##### Alias Records
- **Definition**: Point to Azure resources directly
- **Benefit**: Automatically updates if resource IP changes
- **Supported Resources**: Public IP, Traffic Manager, CDN

##### Auto-Registration (Private DNS)
- **Definition**: Automatically register VMs in private zone
- **Process**: VM created → DNS record auto-created
- **Lifecycle**: VM deleted → DNS record auto-removed

#### Use Cases
- Host public domains and subdomains
- Internal name resolution for Azure resources
- Simplified DNS management
- Integration with Azure services

#### Benefits
- **Reliability**: Azure infrastructure and SLA
- **Security**: Azure RBAC and audit logs
- **Ease of Use**: Managed service, no DNS servers
- **Performance**: Global anycast network
- **Cost-Effective**: Pay per zone and query volume

#### Azure DNS vs Private DNS Zones

| Feature | Azure DNS | Private DNS Zones |
|---------|-----------|-------------------|
| **Scope** | Public internet | Private VNets |
| **Use Case** | Public websites | Internal resources |
| **Registration** | Manual | Auto-registration available |
| **Visibility** | Global | VNet-specific |

## Networking Connectivity

### VPN Gateway
- **Purpose**: Encrypted connection between Azure and on-premises
- **Types**: Site-to-Site, Point-to-Site, VNet-to-VNet
- **Use Case**: Hybrid connectivity, remote access

### ExpressRoute
- **Purpose**: Private dedicated connection to Azure
- **Benefits**: Higher reliability, faster speeds, lower latency
- **Use Case**: Enterprise hybrid scenarios, large data transfers

### Virtual WAN
- **Purpose**: Unified wide area networking
- **Features**: Hub-and-spoke architecture, integrated connectivity
- **Use Case**: Large-scale branch connectivity

## Summary

### Compute Services Overview
- **VMs**: Full control, lift-and-shift, custom configurations
- **Virtual Desktop**: Remote desktop and app access
- **Containers**: Portable, efficient, microservices
- **Functions**: Serverless, event-driven, pay-per-execution
- **App Service**: Managed web hosting, easy deployment

### Networking Services Overview
- **Virtual Networks**: Foundation of Azure networking
- **DNS**: Name resolution for public and private resources

### Key Takeaways
- **Choose compute based on needs**: Control vs Management tradeoff
- **VMs for full control**: When you need specific OS or software
- **Containers for portability**: Modern microservices architectures
- **Functions for events**: Serverless, cost-effective for sporadic workloads
- **VNets are foundational**: Every Azure resource needs networking
- **DNS simplifies management**: No need for custom DNS infrastructure
