# 2.2 Azure Compute and Networking

## Azure Compute Services

### Azure Virtual Machines (VMs)

#### Definition
Infrastructure as a Service (IaaS) offering that provides on-demand, scalable computing resources with full control over the operating system.

#### Key Features
- **Complete Control**: Full control over OS and software
- **Flexible Sizing**: Multiple VM sizes for different workloads
- **Multiple OS Support**: Windows and Linux distributions
- **Custom Images**: Create and deploy custom VM images

#### VM Sizes and Series
- **General Purpose**: B, D, A series - Balanced CPU-to-memory
- **Compute Optimized**: F series - High CPU-to-memory ratio
- **Memory Optimized**: E, M series - High memory-to-CPU ratio
- **Storage Optimized**: L series - High disk throughput and IO
- **GPU**: N series - GPU-enabled for graphics and compute workloads
- **High Performance Compute**: H series - Fastest CPU VMs

#### VM Pricing Options
- **Pay-as-you-go**: Standard hourly pricing
- **Reserved Instances**: 1 or 3-year commitments for cost savings
- **Spot VMs**: Unused capacity at discounted rates
- **Azure Hybrid Benefit**: Use existing Windows licenses

#### Use Cases
- **Lift and Shift**: Migrate existing applications
- **Development and Testing**: Isolated development environments
- **Custom Applications**: Applications requiring specific OS configurations
- **Legacy Applications**: Applications that can't be modernized

### Virtual Machine Scale Sets

#### Definition
A service that lets you create and manage a group of identical, load-balanced VMs that automatically increase or decrease based on demand.

#### Key Features
- **Auto-scaling**: Automatically scale based on metrics
- **Load Distribution**: Built-in load balancing
- **High Availability**: VMs distributed across fault domains
- **Large Scale**: Support for up to 1,000 VM instances

#### Scaling Options
- **Metric-based**: CPU, memory, disk, network metrics
- **Schedule-based**: Scale at specific times
- **Manual**: Scale manually as needed
- **Custom Metrics**: Scale based on application-specific metrics

#### Benefits
- **Cost Effective**: Pay only for running instances
- **Simplified Management**: Single configuration for multiple VMs
- **High Availability**: Automatic distribution across availability zones
- **Integration**: Works with Azure Load Balancer and Application Gateway

### Azure Container Services

#### Azure Container Instances (ACI)

##### Definition
Serverless container service that allows you to run containers without managing servers or orchestrators.

##### Key Features
- **Serverless**: No VM management required
- **Fast Startup**: Containers start in seconds
- **Per-second Billing**: Pay only for running time
- **Multiple OS**: Windows and Linux container support

##### Use Cases
- **Batch Jobs**: Run containers for specific tasks
- **Dev/Test**: Quick container testing environments
- **Application Tasks**: Event-driven applications
- **CI/CD**: Build and deployment tasks

#### Azure Kubernetes Service (AKS)

##### Definition
Managed Kubernetes service that simplifies deploying and managing containerized applications using Kubernetes.

##### Key Features
- **Managed Control Plane**: Microsoft manages Kubernetes masters
- **Integrated Security**: Azure Active Directory integration
- **Auto-scaling**: Cluster and pod auto-scaling
- **Built-in Monitoring**: Azure Monitor integration

##### Benefits
- **Reduced Complexity**: Simplified Kubernetes management
- **Enterprise Ready**: Security, monitoring, and governance features
- **Hybrid Support**: Arc-enabled Kubernetes for hybrid scenarios
- **Cost Effective**: Pay only for agent nodes

##### Use Cases
- **Microservices**: Container orchestration for microservices
- **DevOps**: CI/CD pipelines with containers
- **Modernization**: Modernize existing applications
- **Multi-cloud**: Consistent container platform

### Azure App Service

#### Definition
Platform as a Service (PaaS) for hosting web applications, REST APIs, and mobile backends without managing infrastructure.

#### Supported Platforms
- **Web Apps**: .NET, Java, Ruby, Node.js, PHP, Python
- **API Apps**: RESTful API hosting
- **Mobile Apps**: Mobile backend services
- **Logic Apps**: Workflow automation (now separate service)

#### Key Features
- **Auto-scaling**: Scale based on demand
- **Continuous Deployment**: Integration with GitHub, Azure DevOps
- **Custom Domains**: Use your own domain names
- **SSL Support**: Free SSL certificates
- **Staging Slots**: Deploy to staging before production

#### App Service Plans
- **Free**: Limited resources, no custom domains
- **Shared**: Low-cost option with shared resources
- **Basic**: Dedicated compute, custom domains, SSL
- **Standard**: Auto-scaling, staging slots, daily backups
- **Premium**: Enhanced performance and features
- **Isolated**: Dedicated environment, maximum scale

#### Benefits
- **No Infrastructure Management**: Focus on code, not servers
- **Built-in DevOps**: Integrated CI/CD capabilities
- **Enterprise Features**: Authentication, authorization, monitoring
- **Global Scale**: Deploy to multiple regions

### Azure Functions

#### Definition
Serverless compute service that lets you run event-triggered code without explicitly provisioning or managing infrastructure.

#### Key Features
- **Event-driven**: Triggered by various Azure services
- **Multiple Languages**: C#, Java, JavaScript, Python, PowerShell
- **Pay-per-execution**: Pay only when functions execute
- **Auto-scaling**: Scales automatically based on demand

#### Trigger Types
- **HTTP Trigger**: Respond to HTTP requests
- **Timer Trigger**: Execute on schedule
- **Blob Trigger**: Process file uploads
- **Queue Trigger**: Process queue messages
- **Event Hub Trigger**: Process streaming data

#### Hosting Plans
- **Consumption Plan**: Pay-per-execution, auto-scaling
- **Premium Plan**: Enhanced performance and VNet connectivity
- **Dedicated Plan**: Run on App Service plan with predictable pricing

#### Use Cases
- **Data Processing**: Process files and data streams
- **API Endpoints**: Create lightweight APIs
- **Automation**: Scheduled tasks and workflows
- **Integration**: Connect different services and systems

## Azure Networking Services

### Azure Virtual Network (VNet)

#### Definition
A logically isolated network in Azure that provides a secure way to connect Azure resources and extend on-premises networks.

#### Key Components
- **Address Space**: Define IP address ranges using CIDR notation
- **Subnets**: Divide VNet into smaller network segments
- **Route Tables**: Control traffic routing between subnets
- **Network Security Groups**: Firewall rules for subnets and NICs

#### VNet Features
- **Isolation**: Logically isolated from other VNets
- **Internet Connectivity**: Resources can access internet by default
- **Azure Service Connectivity**: Connect to Azure services privately
- **On-premises Connectivity**: Extend networks to on-premises

#### Subnet Design
- **Public Subnet**: Resources with direct internet access
- **Private Subnet**: Resources without direct internet access
- **DMZ Subnet**: Resources accessible from internet with restrictions
- **Management Subnet**: Administrative access to resources

### VNet Connectivity Options

#### VNet Peering

##### Definition
Connect two VNets to enable resources to communicate with each other as if they were in the same network.

##### Types
- **VNet Peering**: Connect VNets in same region
- **Global VNet Peering**: Connect VNets across regions

##### Benefits
- **Low Latency**: Direct connection between VNets
- **High Bandwidth**: No bandwidth restrictions
- **Cross-region**: Connect VNets globally
- **No Downtime**: Establish connection without service interruption

#### VPN Gateway

##### Definition
Send encrypted traffic between Azure VNet and on-premises networks over the public internet.

##### VPN Types
- **Site-to-Site**: Connect on-premises network to Azure VNet
- **Point-to-Site**: Connect individual client to Azure VNet
- **VNet-to-VNet**: Connect Azure VNets through VPN gateways

##### VPN Gateway SKUs
- **Basic**: Basic connectivity, limited performance
- **VpnGw1/2/3**: Standard performance tiers
- **VpnGw1/2/3AZ**: Availability Zone support

#### ExpressRoute

##### Definition
Private connection between on-premises networks and Azure datacenters, not over public internet.

##### Key Features
- **Private Connectivity**: Dedicated connection, not over internet
- **High Bandwidth**: Up to 100 Gbps connections available
- **Low Latency**: Consistent network performance
- **Global Reach**: Connect to Azure regions worldwide

##### ExpressRoute Models
- **CloudExchange Co-location**: Connect through cloud exchange provider
- **Point-to-Point Ethernet**: Direct connection to Microsoft network
- **Any-to-Any Networks**: Connect through WAN provider
- **ExpressRoute Direct**: Direct connection to Microsoft global network

### Azure DNS

#### Definition
Hosting service for DNS domains that provides name resolution using Microsoft Azure infrastructure.

#### Key Features
- **High Availability**: 100% availability SLA
- **Global Network**: Anycast DNS network
- **Azure Integration**: Manage DNS records alongside Azure resources
- **Private DNS**: Internal name resolution for VNets

#### DNS Zone Types
- **Public DNS Zones**: Publicly accessible DNS records
- **Private DNS Zones**: Internal DNS resolution for VNets

#### Benefits
- **Scalability**: Handle millions of DNS queries
- **Security**: Integration with Azure RBAC
- **Ease of Use**: Manage through Azure portal, PowerShell, CLI
- **Cost-effective**: Pay only for hosted zones and queries

### Load Balancing Services

#### Azure Load Balancer

##### Definition
Layer 4 (TCP/UDP) load balancer that distributes incoming traffic among healthy service instances.

##### Types
- **Public Load Balancer**: Load balance internet traffic to VMs
- **Internal Load Balancer**: Load balance traffic within VNet

##### SKUs
- **Basic**: Free, limited features
- **Standard**: Enhanced features, availability zones, more endpoints

##### Features
- **Health Probes**: Monitor endpoint health
- **Session Persistence**: Route sessions to same backend
- **Outbound Rules**: Control outbound connectivity
- **High Availability**: Zone-redundant and zone-aware options

#### Azure Application Gateway

##### Definition
Web traffic load balancer (Layer 7) that enables you to manage traffic to your web applications.

##### Key Features
- **URL-based Routing**: Route traffic based on URL paths
- **SSL Termination**: Handle SSL encryption/decryption
- **Web Application Firewall**: Protect against web vulnerabilities
- **Auto-scaling**: Scale based on traffic patterns

##### Benefits
- **Application-aware**: Makes routing decisions based on application content
- **Security**: Built-in Web Application Firewall protection
- **Performance**: SSL offloading and connection multiplexing
- **Monitoring**: Integration with Azure Monitor

#### Azure Front Door

##### Definition
Global, scalable entry point that uses Microsoft global edge network to create fast, secure, and widely scalable web applications.

##### Key Features
- **Global Load Balancing**: Route traffic to closest healthy backend
- **SSL Offloading**: Handle SSL termination at edge
- **URL Rewrite**: Modify URLs before forwarding
- **Session Affinity**: Route user sessions to same backend

##### Benefits
- **Global Scale**: Leverage Microsoft's global network
- **Performance**: Reduced latency through edge locations
- **Reliability**: Automatic failover between regions
- **Security**: DDoS protection and Web Application Firewall

### Content Delivery Network (CDN)

#### Definition
Globally distributed network of servers that efficiently deliver web content to users based on geographic location.

#### Azure CDN Providers
- **Microsoft**: Azure CDN from Microsoft
- **Verizon**: Azure CDN from Verizon (Standard/Premium)
- **Akamai**: Azure CDN from Akamai

#### Key Features
- **Global Distribution**: 100+ edge locations worldwide
- **Caching**: Cache static content at edge locations
- **Custom Rules**: Define caching and routing behavior
- **Real-time Analytics**: Monitor performance and usage

#### Benefits
- **Improved Performance**: Faster content delivery to users
- **Reduced Load**: Less traffic to origin servers
- **Global Reach**: Serve content worldwide
- **Cost Savings**: Reduce bandwidth costs

## Network Security

### Network Security Groups (NSGs)

#### Definition
Cloud firewall that filters network traffic to and from Azure resources in an Azure VNet.

#### Key Features
- **Inbound/Outbound Rules**: Control traffic direction
- **Priority-based**: Rules processed by priority (100-4096)
- **5-tuple Filtering**: Source/destination IP, port, protocol
- **Default Rules**: Built-in rules for basic connectivity

#### Application Levels
- **Subnet Level**: Applied to all resources in subnet
- **Network Interface Level**: Applied to specific VM network interface

### Azure Firewall

#### Definition
Managed, cloud-based network security service that protects your Azure VNet resources.

#### Key Features
- **Stateful Firewall**: Built-in high availability and scalability
- **Application Rules**: Filter traffic based on FQDN
- **Network Rules**: Filter traffic based on IP, port, protocol
- **Threat Intelligence**: Block traffic from known malicious sources

#### Benefits
- **Centralized Control**: Single point for network security policies
- **Logging**: Comprehensive logging and monitoring
- **Integration**: Works with Azure Monitor and SIEM solutions
- **Compliance**: Meets various compliance requirements
