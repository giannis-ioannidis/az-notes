# 2.3 Azure Storage

## Azure Storage Overview

### Definition
Azure Storage is a cloud storage solution that provides highly available, secure, durable, scalable, and redundant storage for various data objects.

### Key Characteristics
- **Highly Available**: 99.9% to 99.99% availability SLA
- **Secure**: Encrypted in transit and at rest
- **Scalable**: Virtually unlimited storage capacity
- **Durable**: Multiple copies of data stored
- **Accessible**: Available via REST APIs, SDKs, and tools

### Storage Account

#### Definition
A storage account provides a unique namespace in Azure for your data and contains all of your Azure Storage data objects.

#### Storage Account Types

##### General-purpose v2 (GPv2)
- **Recommended**: Standard storage account type
- **Services**: Blob, File, Queue, Table storage
- **Performance Tiers**: Standard and Premium
- **Access Tiers**: Hot, Cool, Archive

##### General-purpose v1 (GPv1)
- **Legacy**: Older storage account type
- **Limited Features**: No access tiers or latest features
- **Recommendation**: Upgrade to GPv2

##### BlockBlobStorage
- **Specialized**: Premium performance for block blobs
- **Use Cases**: High transaction rates, low latency scenarios
- **Cost**: Higher storage costs, lower transaction costs

##### FileStorage
- **Specialized**: Premium performance for file shares
- **Use Cases**: Enterprise applications requiring high IOPS
- **Protocol**: SMB and NFS protocols

##### BlobStorage
- **Legacy**: Blob-only storage accounts
- **Recommendation**: Use GPv2 instead

#### Performance Tiers

##### Standard
- **Backed by**: Magnetic drives (HDDs)
- **Performance**: Good for most scenarios
- **Cost**: Lower storage costs
- **Use Cases**: Backup, archival, infrequent access

##### Premium
- **Backed by**: Solid-state drives (SSDs)
- **Performance**: High throughput and low latency
- **Cost**: Higher storage costs, lower transaction costs
- **Use Cases**: High-performance applications, databases

## Azure Storage Services

### Azure Blob Storage

#### Definition
Object storage solution optimized for storing massive amounts of unstructured data like text, binary data, images, videos, and documents.

#### Blob Types

##### Block Blobs
- **Use Case**: Text and binary files up to 4.7 TB
- **Features**: Efficient upload, download, and streaming
- **Examples**: Images, videos, documents, backups

##### Append Blobs
- **Use Case**: Optimized for append operations
- **Features**: Ideal for logging scenarios
- **Limitation**: Can't modify existing data, only append

##### Page Blobs
- **Use Case**: Random read/write operations
- **Features**: Optimized for IaaS disks
- **Size**: Up to 8 TB
- **Examples**: Virtual machine disks

#### Access Tiers

##### Hot Tier
- **Use Case**: Frequently accessed data
- **Storage Cost**: Higher storage cost
- **Access Cost**: Lower access cost
- **Examples**: Active websites, applications

##### Cool Tier
- **Use Case**: Infrequently accessed data
- **Storage Time**: Stored for at least 30 days
- **Storage Cost**: Lower storage cost
- **Access Cost**: Higher access cost
- **Examples**: Short-term backup, disaster recovery

##### Archive Tier
- **Use Case**: Rarely accessed data
- **Storage Time**: Stored for at least 180 days
- **Storage Cost**: Lowest storage cost
- **Access Cost**: Highest access cost
- **Retrieval Time**: Several hours
- **Examples**: Long-term backups, compliance data

#### Blob Storage Features
- **Lifecycle Management**: Automatically move blobs between tiers
- **Versioning**: Keep multiple versions of blobs
- **Soft Delete**: Recover accidentally deleted blobs
- **Change Feed**: Track changes to blobs
- **Point-in-time Restore**: Restore to previous state

### Azure Files

#### Definition
Fully managed file shares in the cloud accessible via Server Message Block (SMB) and Network File System (NFS) protocols.

#### Key Features
- **Shared Access**: Multiple VMs can mount same file share
- **Protocol Support**: SMB 2.1, 3.0, 3.1.1 and NFS 4.1
- **Azure Integration**: Works with Azure VMs and on-premises
- **Backup**: Integration with Azure Backup service

#### Performance Tiers

##### Standard
- **Performance**: Up to 1,000 IOPS per share
- **Capacity**: Up to 100 TB per share
- **Use Cases**: General file shares, content repositories

##### Premium
- **Performance**: Up to 100,000 IOPS per share
- **Capacity**: Up to 100 TB per share
- **Latency**: Sub-millisecond latency
- **Use Cases**: High-performance applications, databases

#### Use Cases
- **Lift and Shift**: Replace on-premises file servers
- **Shared Application Data**: Configuration files, data files
- **Development Tools**: Shared development environments
- **Diagnostics**: Store logs and metrics

#### Azure File Sync
- **Definition**: Service that centralizes file shares in Azure Files while maintaining local access
- **Benefits**: Cache frequently accessed files locally
- **Features**: Cloud tiering, multi-site sync, backup integration

### Azure Queue Storage

#### Definition
Service for storing large numbers of messages that can be accessed from anywhere in the world via HTTP or HTTPS.

#### Key Features
- **Message Size**: Up to 64 KB per message
- **Queue Size**: Virtually unlimited number of messages
- **TTL**: Configurable time-to-live for messages
- **Visibility Timeout**: Hide messages during processing

#### Message Processing
- **FIFO**: First-in, first-out processing
- **At-Least-Once**: Messages delivered at least once
- **Visibility Timeout**: Prevent multiple consumers processing same message

#### Use Cases
- **Application Decoupling**: Decouple application components
- **Load Leveling**: Handle traffic spikes
- **Async Processing**: Process work items asynchronously
- **Communication**: Communication between application tiers

### Azure Table Storage

#### Definition
NoSQL key-value store for rapid development using massive semi-structured datasets.

#### Key Characteristics
- **Schema-less**: No fixed schema required
- **Partitioning**: Data partitioned using partition key
- **Scalability**: Handles billions of entities
- **Indexing**: Automatic indexing on partition and row keys

#### Table Structure
- **Partition Key**: Groups related entities together
- **Row Key**: Unique identifier within partition
- **Timestamp**: Automatic versioning
- **Properties**: Up to 252 custom properties per entity

#### Use Cases
- **User Data**: Store user profiles and preferences
- **Device Information**: IoT device telemetry data
- **Metadata**: Store metadata for other services
- **Configuration**: Application configuration data

## Azure Storage Security

### Encryption

#### Encryption at Rest
- **SSE**: Storage Service Encryption enabled by default
- **Key Management**: Microsoft-managed or customer-managed keys
- **Algorithms**: AES 256-bit encryption
- **Scope**: All storage services encrypted

#### Encryption in Transit
- **HTTPS**: All data transferred over HTTPS by default
- **SMB 3.0**: Encrypted file share access
- **Client-side**: Optional client-side encryption

### Access Control

#### Shared Access Signatures (SAS)

##### Definition
Provide secure delegated access to storage account resources without sharing account keys.

##### SAS Types
- **Account SAS**: Access to multiple services in storage account
- **Service SAS**: Access to specific service (Blob, File, Queue, Table)
- **User Delegation SAS**: Secured with Azure AD credentials (Blob only)

##### SAS Permissions
- **Read**: Read data
- **Write**: Write data
- **Delete**: Delete data
- **List**: List containers/files
- **Add**: Add data to queues/tables
- **Create**: Create new resources
- **Update**: Update existing data
- **Process**: Process queue messages

#### Access Keys
- **Primary/Secondary Keys**: Full access to storage account
- **Regeneration**: Can regenerate keys without downtime
- **Best Practice**: Rotate keys regularly

#### Azure Active Directory Integration
- **RBAC**: Role-based access control for storage resources
- **Managed Identities**: Secure access without storing credentials
- **Fine-grained Access**: Granular permissions for different operations

### Network Security

#### Private Endpoints
- **Definition**: Private IP address from your VNet for storage account
- **Benefits**: Traffic stays within Microsoft network
- **Security**: Eliminates exposure to public internet

#### Service Endpoints
- **Definition**: Direct connection from VNet to Azure services
- **Benefits**: Improved security and performance
- **Scope**: VNet level configuration

#### Firewall Rules
- **IP Rules**: Allow specific IP addresses or ranges
- **VNet Rules**: Allow specific VNets and subnets
- **Default Action**: Allow or deny all traffic

## Data Redundancy

### Locally Redundant Storage (LRS)

#### Definition
Replicates data three times within a single physical location in primary region.

#### Characteristics
- **Copies**: 3 copies in same datacenter
- **Durability**: 99.999999999% (11 9's)
- **Cost**: Lowest cost option
- **Protection**: Protects against local hardware failures

#### Use Cases
- **Cost-sensitive**: Applications with strict budget constraints
- **Replaceable Data**: Data that can be easily reconstructed
- **Compliance**: Data must stay in specific location

### Zone-Redundant Storage (ZRS)

#### Definition
Replicates data across three availability zones in primary region.

#### Characteristics
- **Copies**: 3 copies across availability zones
- **Durability**: 99.9999999999% (12 9's)
- **Availability**: Continues if one zone fails
- **Cost**: Higher than LRS

#### Use Cases
- **High Availability**: Applications requiring zone-level redundancy
- **Consistency**: Strong consistency across zones
- **Disaster Recovery**: Protection against zone failures

### Geo-Redundant Storage (GRS)

#### Definition
Replicates data to secondary region hundreds of miles away from primary region.

#### Characteristics
- **Primary**: 3 copies using LRS in primary region
- **Secondary**: 3 copies using LRS in paired region
- **Durability**: 99.99999999999999% (16 9's)
- **Access**: Read-only access to secondary (RA-GRS)

#### Use Cases
- **Disaster Recovery**: Protection against regional disasters
- **Compliance**: Requirements for geographic distribution
- **Business Continuity**: Critical business applications

### Geo-Zone-Redundant Storage (GZRS)

#### Definition
Combines benefits of ZRS in primary region with GRS replication to secondary region.

#### Characteristics
- **Primary**: 3 copies across availability zones
- **Secondary**: 3 copies using LRS in paired region
- **Durability**: Highest durability option
- **Cost**: Most expensive option

#### Use Cases
- **Mission Critical**: Applications requiring maximum durability
- **Regulatory**: Strict compliance requirements
- **Enterprise**: Large enterprise applications

## Storage Management Tools

### Azure Storage Explorer
- **Definition**: Standalone application for managing Azure Storage
- **Platforms**: Windows, macOS, Linux
- **Features**: Upload, download, manage blobs, files, queues, tables

### AzCopy
- **Definition**: Command-line utility for copying data to/from storage
- **Performance**: High-performance data transfer
- **Features**: Resume transfers, sync directories, cross-account copy

### Azure PowerShell
- **Modules**: Az.Storage module for storage management
- **Automation**: Script storage operations
- **Integration**: Works with other Azure services

### Azure CLI
- **Commands**: az storage commands for storage management
- **Cross-platform**: Works on Windows, macOS, Linux
- **Scripting**: Bash and PowerShell scripting support

## Storage Cost Optimization

### Cost Factors
- **Storage Capacity**: Amount of data stored
- **Transactions**: Number of read/write operations
- **Data Transfer**: Outbound data transfer costs
- **Redundancy**: Higher redundancy = higher cost

### Optimization Strategies
- **Access Tiers**: Use appropriate tier for access patterns
- **Lifecycle Management**: Automatically move data between tiers
- **Reserved Capacity**: Commit to storage for discounts
- **Compression**: Compress data before storing
- **Deduplication**: Eliminate duplicate data

### Monitoring and Analytics
- **Storage Analytics**: Built-in metrics and logging
- **Azure Monitor**: Centralized monitoring and alerting
- **Cost Analysis**: Track and analyze storage costs
- **Capacity Planning**: Forecast future storage needs
