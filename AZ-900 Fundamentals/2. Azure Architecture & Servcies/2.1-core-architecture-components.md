# 2.1 Core Azure Architecture Components

## Physical Infrastructure

The physical infrastructure represents the actual hardware and datacenters that power Azure services globally.

### Azure Geographies

#### Definition
A discrete market containing one or more regions that preserves data residency and compliance boundaries.

#### Key Features
- **Data Residency**: Data stays within geographic boundaries
- **Compliance**: Meets regulatory requirements
- **Disaster Recovery**: Cross-region replication within geography
- **Tax Jurisdiction**: Aligns with local tax laws

#### Examples
- **Americas**: United States, Canada, Brazil
- **Europe**: European Union countries, United Kingdom
- **Asia Pacific**: Japan, Australia, India, Southeast Asia

### Azure Regions

#### Definition
A set of datacenters deployed within a latency-defined perimeter and connected through a dedicated regional low-latency network.

#### Key Characteristics
- **Geographic Distribution**: 60+ regions worldwide
- **Paired Regions**: Each region paired with another in same geography
- **Service Availability**: Not all services available in every region
- **Compliance**: Regional compliance and data sovereignty

#### Region Selection Factors
1. **Location**: Proximity to users for reduced latency
2. **Features**: Service and feature availability
3. **Compliance**: Data residency and regulatory requirements
4. **Pricing**: Regional pricing variations

#### Special Azure Regions
- **Government Regions**: US Gov Virginia, US Gov Texas, US Gov Arizona
- **China Regions**: Operated by 21Vianet
- **Germany Regions**: Data trustee model for enhanced privacy

### Availability Zones

#### Definition
Physically separate datacenters within an Azure region, each with independent power, cooling, and networking.

#### Key Features
- **Physical Separation**: Minimum 3 zones per supported region
- **Independent Infrastructure**: Separate power, cooling, networking
- **High-Speed Connectivity**: Connected via private fiber-optic networks
- **Fault Isolation**: Failure in one zone doesn't affect others

#### Zone-Redundant Services
- **Virtual Machines**: Deploy VMs across zones
- **Managed Disks**: Zone-redundant storage
- **Load Balancer**: Standard Load Balancer supports zones
- **SQL Database**: Zone-redundant configuration available

#### Benefits
- **99.99% SLA**: Higher SLA than single zone deployments
- **Automatic Failover**: Services can failover between zones
- **Data Protection**: Synchronous replication across zones
- **Business Continuity**: Protection against datacenter failures

### Region Pairs

#### Definition
Each Azure region is paired with another region within the same geography, at least 300 miles away.

#### Key Characteristics
- **Geographic Separation**: Minimum 300 miles apart
- **Planned Updates**: Only one region updated at a time
- **Data Residency**: Both regions within same geography
- **Priority Recovery**: One region prioritized during outages

#### Examples
- **East US** paired with **West US**
- **North Europe** paired with **West Europe**
- **East Asia** paired with **Southeast Asia**
- **Australia East** paired with **Australia Southeast**

#### Benefits
- **Disaster Recovery**: Cross-region backup and replication
- **Platform Updates**: Reduced risk during Azure updates
- **Data Recovery**: Priority recovery in widespread outages
- **Compliance**: Maintains data residency requirements

### Physical Infrastructure Hierarchy
```
Geography
└── Region (Primary)
    ├── Availability Zone 1
    ├── Availability Zone 2
    └── Availability Zone 3
└── Region (Paired)
    ├── Availability Zone 1
    ├── Availability Zone 2
    └── Availability Zone 3
```

## Management Infrastructure

The management infrastructure provides the organizational structure and tools for managing Azure resources.

### Management Groups

#### Definition
Containers that help you manage access, policy, and compliance across multiple subscriptions.

#### Key Features
- **Hierarchy**: Up to 6 levels of depth
- **Policy Inheritance**: Policies applied to management group apply to all child resources
- **RBAC**: Role assignments inherited by child resources
- **Flexible Structure**: Organize subscriptions by business needs

#### Use Cases
- **Multi-department Organizations**: Separate management groups per department
- **Geographic Structure**: Organize by regions or countries
- **Environment Separation**: Development, testing, production
- **Cost Management**: Separate billing and cost tracking

#### Hierarchy Example
```
Root Management Group
├── Production Management Group
│   ├── Production Subscription 1
│   └── Production Subscription 2
└── Development Management Group
    ├── Dev Subscription 1
    └── Test Subscription 1
```

### Azure Subscriptions

#### Definition
A logical unit of Azure services that's linked to an Azure account and serves as a billing boundary.

#### Key Characteristics
- **Billing Boundary**: Separate invoice per subscription
- **Access Control Boundary**: Different access permissions
- **Resource Limits**: Service limits apply per subscription
- **Policy Boundary**: Policies can be applied at subscription level

#### Subscription Types
- **Free**: $200 credit for 30 days, limited free services
- **Pay-As-You-Go**: Pay for what you use
- **Enterprise Agreement**: Volume licensing for enterprises
- **Student**: Free credits for students
- **Visual Studio**: Monthly credits for Visual Studio subscribers

#### Multiple Subscription Strategies
- **Environment Separation**: Dev, Test, Production subscriptions
- **Organizational Structure**: Department-based subscriptions
- **Billing Separation**: Different cost centers or projects
- **Regulatory Compliance**: Separate subscriptions for compliance requirements

### Resource Groups

#### Definition
A container that holds related resources for an Azure solution, allowing you to manage resources as a group.

#### Key Characteristics
- **Logical Grouping**: Resources don't need to be in same region
- **Access Control**: RBAC applied at resource group level
- **Billing**: Cost tracking and management
- **Lifecycle Management**: Deploy, update, delete resources together

#### Resource Group Properties
- **Location**: Resource group has location (metadata storage)
- **Resources**: Can contain resources from different regions
- **Permissions**: Inherited by contained resources
- **Tags**: Can be tagged for organization and billing

#### Best Practices
- **Group Related Resources**: Resources with same lifecycle
- **Consider Access Requirements**: Group resources with similar access needs
- **Environment Separation**: Separate resource groups for different environments
- **Naming Convention**: Use consistent naming standards

### Azure Resources

#### Definition
A manageable item available through Azure, such as virtual machines, storage accounts, web apps, databases.

#### Resource Properties
- **Resource Type**: The kind of resource (VM, storage account, etc.)
- **Location**: The region where resource is deployed
- **Resource Group**: The container holding the resource
- **Tags**: Key-value pairs for organization
- **Locks**: Prevent accidental deletion or modification

#### Common Azure Resources
- **Compute**: Virtual Machines, App Services, Functions
- **Storage**: Storage Accounts, Disks, File Shares
- **Networking**: Virtual Networks, Load Balancers, Application Gateways
- **Databases**: SQL Database, Cosmos DB, MySQL
- **AI/ML**: Cognitive Services, Machine Learning

### Management Infrastructure Hierarchy
```
Management Groups (Optional)
└── Subscription
    └── Resource Groups
        └── Resources
```

## Azure Resource Manager (ARM)

### Definition
The deployment and management service for Azure that provides a consistent management layer for creating, updating, and deleting resources.

### Key Features
- **Consistent Interface**: Same API for portal, PowerShell, CLI, REST
- **Resource Organization**: Organize resources in resource groups
- **Access Control**: Integrate with Azure Active Directory
- **Tagging**: Apply tags to resources for organization
- **Declarative Templates**: Define infrastructure as code

### ARM Templates

#### Definition
JSON files that define the infrastructure and configuration for your project using declarative syntax.

#### Benefits
- **Consistency**: Deploy same environment multiple times
- **Orchestration**: ARM handles deployment order and dependencies
- **Version Control**: Templates can be stored in source control
- **Parameterization**: Use parameters for different environments
- **Validation**: Templates validated before deployment

#### Template Structure
```json
{
  "$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
  "contentVersion": "1.0.0.0",
  "parameters": {},
  "variables": {},
  "resources": [],
  "outputs": {}
}
```

### Bicep

#### Definition
A domain-specific language (DSL) that uses declarative syntax to deploy Azure resources, providing a simpler authoring experience than ARM templates.

#### Advantages over ARM Templates
- **Simpler Syntax**: More readable and easier to write
- **Type Safety**: Strong typing support
- **Modularity**: Reusable modules
- **Tooling**: Better IDE support and IntelliSense

#### Example Bicep Code
```bicep
param storageAccountName string
param location string = resourceGroup().location

resource storageAccount 'Microsoft.Storage/storageAccounts@2021-04-01' = {
  name: storageAccountName
  location: location
  sku: {
    name: 'Standard_LRS'
  }
  kind: 'StorageV2'
}
```

## Azure Arc (Hybrid Management)

### Definition
A service that extends Azure management capabilities to on-premises, edge, and multi-cloud environments.

### Supported Resources
- **Azure Arc-enabled servers**: On-premises Windows and Linux machines
- **Azure Arc-enabled Kubernetes**: Kubernetes clusters anywhere
- **Azure Arc-enabled data services**: SQL Managed Instance, PostgreSQL
- **Azure Arc-enabled SQL Server**: SQL Server instances on-premises

### Benefits
- **Unified Management**: Manage hybrid resources from Azure portal
- **Compliance**: Apply Azure policies to on-premises resources
- **Security**: Extend Azure security capabilities
- **Monitoring**: Use Azure Monitor for hybrid environments

## Summary

### Physical Infrastructure
The foundation of Azure's global presence:
- **Geographies** provide data residency and compliance boundaries
- **Regions** offer localized services and reduced latency
- **Availability Zones** ensure high availability within regions
- **Region Pairs** enable disaster recovery across regions

### Management Infrastructure
The organizational framework for Azure resources:
- **Management Groups** provide enterprise-scale organization
- **Subscriptions** serve as billing and access boundaries
- **Resource Groups** enable logical grouping and management
- **Resources** are the actual Azure services you deploy

### Key Takeaways
- **Global Scale**: Physical infrastructure spans 60+ regions worldwide
- **High Availability**: Multiple layers of redundancy built-in
- **Flexible Organization**: Management hierarchy adapts to business needs
- **Consistent Management**: ARM provides unified deployment and management
- **Hybrid Ready**: Azure Arc extends management beyond Azure
