# 1.1 Cloud Computing

## What is Cloud Computing?

Cloud computing is the delivery of computing services—including servers, storage, databases, networking, software, analytics, and intelligence—over the Internet ("the cloud") to offer faster innovation, flexible resources, and economies of scale.

### Key Characteristics
- **On-Demand**: Resources available when you need them
- **Internet-Based**: Accessed through web browsers or APIs
- **Shared Resources**: Multiple customers share the same physical infrastructure
- **Pay-as-You-Use**: Only pay for what you consume
- **Globally Accessible**: Available from anywhere with internet connection

### Simple Analogy
Think of cloud computing like electricity from a power company:
- You don't build your own power plant
- You plug into the grid and use what you need
- You pay only for what you consume
- The power company handles maintenance and infrastructure

## Shared Responsibility Model

The shared responsibility model defines which security and operational tasks are handled by the cloud provider versus the customer.

### Cloud Provider Responsibilities
**"Security OF the Cloud"**
- Physical security of datacenters
- Hardware maintenance and replacement
- Network infrastructure
- Host operating system patches
- Hypervisor security
- Physical network controls

### Customer Responsibilities
**"Security IN the Cloud"**
- Data classification and protection
- Identity and access management
- Application-level security
- Operating system updates (for VMs)
- Network traffic protection
- Firewall configuration

### Shared Responsibilities
- **Patch Management**: Provider patches infrastructure, customer patches guest OS and applications
- **Configuration Management**: Provider secures infrastructure, customer configures security settings
- **Awareness & Training**: Both parties need security awareness

### Responsibility by Service Type

#### Infrastructure as a Service (IaaS)
- **Customer**: Most responsible (OS, applications, data, runtime, middleware)
- **Provider**: Physical infrastructure, virtualization, networking

#### Platform as a Service (PaaS)
- **Customer**: Applications, data, user access
- **Provider**: Runtime, middleware, OS, infrastructure

#### Software as a Service (SaaS)
- **Customer**: Data, user access, device management
- **Provider**: Everything else (applications, runtime, OS, infrastructure)

## Cloud Models

### Deployment Models

#### Public Cloud
**Definition**: Cloud resources owned and operated by third-party provider, delivered over the internet.

**Characteristics**:
- Resources shared among multiple organizations
- Accessed via internet
- Managed by cloud service provider

**Benefits**:
- Lower costs (no hardware purchase)
- High scalability
- No maintenance required
- High availability

**Use Cases**:
- Web applications
- Development and testing
- Email and productivity apps

#### Private Cloud
**Definition**: Cloud infrastructure used exclusively by a single organization.

**Characteristics**:
- Dedicated to single organization
- Can be on-premises or hosted
- Higher control and security

**Benefits**:
- Enhanced security and privacy
- Greater control over resources
- Customization options
- Regulatory compliance

**Use Cases**:
- Highly regulated industries
- Sensitive data processing
- Custom business applications

#### Hybrid Cloud
**Definition**: Combination of public and private clouds, connected to work together.

**Characteristics**:
- Combines public and private benefits
- Data and applications can move between environments
- Unified management across both environments

**Benefits**:
- Flexibility and choice
- Cost optimization
- Gradual cloud migration
- Disaster recovery options

**Use Cases**:
- Burst to cloud for peak capacity
- Keep sensitive data private
- Backup and disaster recovery

### Service Models

#### Infrastructure as a Service (IaaS)
**What You Get**: Virtual machines, storage, networks
**What You Manage**: Operating systems, applications, data
**Examples**: Azure Virtual Machines, Azure Storage

#### Platform as a Service (PaaS)
**What You Get**: Development platform, database services, web services
**What You Manage**: Applications and data
**Examples**: Azure App Service, Azure SQL Database

#### Software as a Service (SaaS)
**What You Get**: Complete applications
**What You Manage**: User data and access
**Examples**: Microsoft 365, Salesforce

## Consumption-Based Model

The consumption-based model means you pay only for the cloud services you use, similar to how you pay for utilities like electricity or water.

### Traditional IT Model (CapEx)
**Capital Expenditure Approach**:
- Large upfront investment in servers, storage, networking
- Purchase hardware before you need it
- Costs depreciated over 3-5 years
- Risk of over-provisioning (wasted money) or under-provisioning (poor performance)

**Example**: Buy $100,000 server that sits 50% idle

### Cloud Model (OpEx)
**Operational Expenditure Approach**:
- Pay monthly based on actual usage
- No upfront hardware costs
- Costs scale with your business needs
- Resources can be adjusted in real-time

**Example**: Pay $1,000/month when busy, $200/month when quiet

### Key Benefits of Consumption-Based Model

#### Cost Efficiency
- **No Wasted Resources**: Pay only for what you use
- **No Upfront Investment**: Start small and grow
- **Predictable Budgets**: Better cost forecasting

#### Flexibility
- **Scale Up**: Add resources during busy periods
- **Scale Down**: Reduce costs during quiet periods
- **Try New Services**: Experiment without major investments

#### Financial Advantages
- **Cash Flow**: Preserve capital for core business
- **Tax Benefits**: OpEx vs CapEx accounting advantages
- **Risk Reduction**: No stranded assets from technology changes

### Common Pricing Models

#### Pay-As-You-Go
- Charged based on actual consumption
- No commitments required
- Highest per-unit cost but maximum flexibility

#### Reserved Instances
- Commit to specific resources for 1-3 years
- Significant discounts (up to 70% off)
- Good for predictable workloads

#### Spot Pricing
- Use excess capacity at steep discounts
- Can be interrupted when capacity needed elsewhere
- Great for flexible, fault-tolerant workloads

### Real-World Example
**Traditional Approach**:
- Buy $50,000 server for peak capacity
- Use 30% capacity on average
- Effective cost: $167,000 over 3 years

**Cloud Approach**:
- Pay for actual usage
- Scale automatically with demand
- Total cost: $75,000 over 3 years
- **Savings**: $92,000 (55% reduction)
