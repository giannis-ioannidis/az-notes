# 3.1 Azure Cost Management

## Cost Management Overview

### Definition
Azure Cost Management is a suite of tools that help you monitor, allocate, and optimize your cloud costs across Azure and other cloud providers.

### Key Capabilities
- **Cost Analysis**: Understand where money is being spent
- **Budgets**: Set spending limits and alerts
- **Recommendations**: Get suggestions for cost optimization
- **Exports**: Automate cost data sharing
- **Cost Allocation**: Distribute costs across departments or projects

## Factors Affecting Azure Costs

### 1. Resource Types
Different Azure services have different pricing models:

#### Compute Services
- **Virtual Machines**: Pay for compute hours
- **App Service**: Based on hosting plan tier
- **Functions**: Pay-per-execution or hosting plan
- **Container Instances**: Pay for vCPU and memory per second

#### Storage Services
- **Blob Storage**: Based on storage amount and access tier
- **SQL Database**: Compute and storage separately priced
- **Cosmos DB**: Request units and storage
- **File Storage**: Premium vs. standard pricing

#### Networking Services
- **Data Transfer**: Inbound free, outbound charged
- **Load Balancer**: Rules and data processed
- **VPN Gateway**: Gateway hours and data transfer
- **CDN**: Data transfer and requests

### 2. Resource Usage
- **Consumption-based**: Pay only for what you use
- **Time-based**: Charged per hour or minute
- **Transaction-based**: Per operation or request
- **Data-based**: Amount of data processed or stored

### 3. Geographic Location
```
Region              Relative Cost
East US             Baseline (100%)
West US             Similar (100-110%)
West Europe         Higher (110-120%)
Southeast Asia      Lower (90-100%)
Brazil South        Higher (120-140%)
```

#### Factors Affecting Regional Pricing
- **Local Infrastructure Costs**: Power, cooling, real estate
- **Regulatory Requirements**: Compliance and legal costs
- **Market Competition**: Local cloud provider competition
- **Currency Exchange**: Exchange rate fluctuations

### 4. Azure Marketplace
- **Third-party Solutions**: Additional costs for partner solutions
- **License Types**: BYOL (Bring Your Own License) vs. pay-as-you-go
- **Support Levels**: Different support tiers with varying costs

## Pricing Models

### 1. Pay-As-You-Go (PAYG)
- **No Upfront Commitment**: Start using immediately
- **Flexible**: Scale up or down as needed
- **Higher Unit Cost**: Premium for flexibility
- **Best For**: Development, testing, variable workloads

### 2. Reserved Instances
- **1 or 3 Year Commitment**: Commit to using resources
- **Significant Savings**: Up to 72% compared to pay-as-you-go
- **Exchange/Cancellation**: Limited flexibility to change
- **Best For**: Steady-state workloads, production environments

#### Reserved Instance Types
```sql
-- Virtual Machines: Reserve compute capacity
-- SQL Database: Reserve vCore capacity  
-- Cosmos DB: Reserve throughput capacity
-- Storage: Reserve storage capacity
-- App Service: Reserve hosting plan capacity
```

### 3. Spot Instances
- **Unused Capacity**: Use Azure's excess capacity
- **Up to 90% Savings**: Significant cost reduction
- **Eviction Risk**: Can be reclaimed with 30-second notice
- **Best For**: Batch processing, dev/test, fault-tolerant workloads

### 4. Hybrid Benefit
- **Existing Licenses**: Use on-premises licenses in Azure
- **Windows Server**: Save on Windows VM costs
- **SQL Server**: Apply SQL licenses to Azure SQL Database
- **Savings**: Up to 40% on Windows VMs, up to 30% on SQL Database

##### Azure Costs  
- **Compute**: Virtual machines, containers, serverless
- **Storage**: Blob, file, database storage
- **Networking**: Data transfer, load balancing
- **Security**: Advanced security services
- **Management**: Monitoring, backup, governance

## Cost Optimization Strategies

### 1. Right-sizing Resources

#### Virtual Machines
```
Current: Standard D4s v3 (4 vCPUs, 16 GB)
Usage: Average 15% CPU, 6 GB memory
Recommendation: Standard D2s v3 (2 vCPUs, 8 GB)  
Savings: $150/month per VM
```

#### Databases
```
Current: SQL Database S3 (100 DTU)
Usage: Average 30 DTU utilization
Recommendation: SQL Database S1 (20 DTU) with auto-scaling
Savings: $45/month per database
```

### 2. Reserved Instances Strategy
```
Workload Analysis:
- Production VMs: 95% uptime → Reserve 1-year
- Development: 60% uptime → Pay-as-you-go
- Testing: 40% uptime → Use Spot instances

Reservation Strategy:
- Year 1: Reserve 70% of steady capacity
- Year 2: Increase to 80% based on usage patterns
- Year 3: Optimize mix based on workload changes
```

### 3. Storage Optimization

#### Blob Storage Tiers
```
Data Access Pattern Analysis:
- Frequently accessed (Hot): $0.0184/GB/month
- Monthly access (Cool): $0.01/GB/month  
- Rare access (Archive): $0.00099/GB/month

Strategy:
- Keep current month in Hot tier
- Move data older than 30 days to Cool
- Archive data older than 1 year
```

#### Lifecycle Management
```json
{
  "rules": [
    {
      "name": "optimizeStorage",
      "type": "Lifecycle",
      "definition": {
        "filters": {
          "blobTypes": ["blockBlob"]
        },
        "actions": {
          "baseBlob": {
            "tierToCool": {"daysAfterModificationGreaterThan": 30},
            "tierToArchive": {"daysAfterModificationGreaterThan": 365},
            "delete": {"daysAfterModificationGreaterThan": 2555}
          }
        }
      }
    }
  ]
}
```

### 4. Automation for Cost Control

#### Auto-shutdown Policies
```powershell
# PowerShell script to auto-shutdown VMs
$resourceGroup = "Development-RG"
$VMs = Get-AzVM -ResourceGroupName $resourceGroup

foreach ($VM in $VMs) {
    # Shutdown at 6 PM on weekdays
    $shutdownTime = "18:00"
    $timeZone = "Eastern Standard Time"
    
    Set-AzVMAutoShutdownPolicy -ResourceGroupName $resourceGroup `
        -VMName $VM.Name `
        -ScheduledShutdownTime $shutdownTime `
        -ScheduledShutdownTimeZone $timeZone `
        -NotificationEmail "admin@company.com"
}
```

#### Scale Sets Auto-scaling
```json
{
  "profiles": [
    {
      "name": "businessHours",
      "capacity": {
        "minimum": "2",
        "maximum": "10", 
        "default": "2"
      },
      "rules": [
        {
          "scaleAction": {
            "direction": "Increase",
            "type": "ChangeCount",
            "value": "1",
            "cooldown": "PT5M"
          },
          "metricTrigger": {
            "metricName": "Percentage CPU",
            "threshold": 75
          }
        }
      ]
    }
  ]
}
```

## Cost Monitoring and Alerts

### 1. Budget Alerts Configuration

#### Department-level Budgets
```
Marketing Department:
- Monthly Budget: $2,000
- Alert at 75%: $1,500
- Alert at 90%: $1,800
- Action at 100%: Notify manager + disable expensive resources

IT Department:  
- Monthly Budget: $8,000
- Alert at 80%: $6,400
- Alert at 95%: $7,600
- Action at 100%: Require approval for new resources
```

#### Project-based Budgets
```
Project Alpha:
- Total Budget: $50,000 (6 months)
- Monthly Budget: $8,333
- Alerts: 50%, 75%, 90% thresholds
- Auto-actions: Scale down non-production at 85%

Project Beta:
- Total Budget: $25,000 (3 months)  
- Monthly Budget: $8,333
- Critical threshold: 90%
- Emergency contact: Project manager + finance
```

### 2. Cost Anomaly Detection
```
Anomaly Examples:
- VM count increased by 50% overnight
- Storage costs doubled in one week  
- Network egress charges 10x normal
- New expensive services deployed

Alert Configuration:
- Threshold: 25% increase from baseline
- Time window: Compare to last 30 days
- Recipients: Cloud administrators + finance team
- Action: Investigate within 2 hours
```

### 3. Chargeback and Showback

#### Chargeback Model
```
Cost Allocation Rules:
- Direct Assignment: VM costs to owning department
- Shared Services: Storage costs split proportionally
- Overhead: Management costs 5% markup

Monthly Reporting:
Department A: $15,000 (includes $750 overhead)
Department B: $8,000 (includes $400 overhead)  
Department C: $12,000 (includes $600 overhead)
```

#### Showback Model
```
Cost Visibility Reports:
- Show actual consumption per department
- Include optimization recommendations
- Compare to budget and forecast
- No actual billing/charging

Benefits:
- Increase cost awareness
- Drive optimization behaviors
- Prepare for future chargeback model
```

## Cost Management Best Practices

### 1. Governance Framework
- **Naming Standards**: Consistent resource naming for cost tracking
- **Tagging Strategy**: Use tags for cost allocation and reporting
- **Resource Groups**: Organize resources by lifecycle and ownership
- **Subscriptions**: Separate by environment or department for cost isolation

### 2. Regular Reviews
- **Weekly**: Review anomalies and unexpected costs
- **Monthly**: Analyze trends and optimization opportunities  
- **Quarterly**: Review reservations and long-term commitments
- **Annually**: Evaluate overall cloud strategy and TCO

### 3. Team Education
- **Cost Awareness Training**: Educate developers on cost implications
- **Best Practices**: Share optimization techniques and strategies
- **Tool Training**: Ensure teams can use cost management tools
- **Incentives**: Align cost optimization with team goals
