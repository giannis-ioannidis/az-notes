# 3.3 Azure Deployment Tools

## Deployment Tools Overview

### Purpose of Deployment Tools
- **Consistency**: Deploy identical environments repeatedly
- **Efficiency**: Automate manual deployment processes
- **Version Control**: Track and manage infrastructure changes
- **Scalability**: Deploy to multiple environments simultaneously
- **Reduced Errors**: Eliminate human mistakes in deployment

### Types of Deployment
- **Manual Deployment**: Using Azure portal GUI
- **Scripted Deployment**: Using command-line tools
- **Template-based Deployment**: Using infrastructure as code
- **CI/CD Integration**: Automated deployment pipelines

## Azure Portal

### Definition
Web-based unified console that provides an alternative to command-line tools for managing Azure resources through a graphical interface.

### Key Features

#### Dashboard and Customization
- **Custom Dashboards**: Create personalized views of resources
- **Pinning Resources**: Quick access to frequently used resources
- **Resource Tiles**: Visual representations of resource status
- **Shared Dashboards**: Collaborate with team members

#### Resource Management
- **Resource Creation**: Step-by-step wizards for creating resources
- **Resource Monitoring**: Built-in monitoring and alerting
- **Cost Analysis**: Integrated cost management tools
- **Support Integration**: Direct access to support tickets

#### Portal Features
```
Navigation Elements:
├── Left Navigation Pane
│   ├── All services
│   ├── Resource groups  
│   ├── All resources
│   └── Favorites
├── Top Menu Bar
│   ├── Search bar
│   ├── Cloud Shell
│   ├── Notifications
│   └── Settings
└── Main Content Area
    ├── Resource details
    ├── Configuration options
    └── Activity logs
```

### Use Cases
- **Learning and Exploration**: Ideal for beginners to understand Azure services
- **One-off Deployments**: Quick deployment of individual resources
- **Monitoring and Management**: Day-to-day resource management
- **Troubleshooting**: Visual debugging and configuration review

### Limitations
- **Not Scalable**: Manual process doesn't scale to multiple environments
- **No Version Control**: Changes aren't tracked or versioned
- **Error Prone**: Manual configuration can lead to inconsistencies
- **No Automation**: Cannot integrate with CI/CD pipelines

### Definition
Browser-based shell experience for managing Azure resources, available as both Bash and PowerShell environments.

### Key Features

#### Two Shell Options
- **Bash**: Linux-based shell with Azure CLI pre-installed
- **PowerShell**: Cross-platform PowerShell with Azure PowerShell modules

#### Pre-installed Tools
```

├── Azure CLI (az)
├── Azure PowerShell (Az modules)
├── kubectl (Kubernetes CLI)
├── Terraform
├── Ansible
├── Git
├── Docker CLI
├── Node.js and npm
├── Python and pip
└── .NET Core SDK
```

#### Cloud Storage Integration
- **Persistent Storage**: 5 GB Azure File share for home directory
- **Cross-session Persistence**: Files and settings persist across sessions
- **Multiple Access**: Same storage accessible from different locations

## Azure PowerShell

### Definition
Cross-platform command-line tool and scripting environment for managing Azure resources using PowerShell cmdlets.

### Installation Options
```powershell
# Install on Windows (PowerShell 5.1 or PowerShell 7+)
Install-Module -Name Az -Scope CurrentUser -Repository PSGallery -Force

# Install on macOS/Linux (PowerShell 7+)  
Install-Module -Name Az -Scope CurrentUser -Repository PSGallery -Force

# Install specific modules
Install-Module -Name Az.Accounts, Az.Resources, Az.Storage
```

### Authentication
```powershell
# Interactive login
Connect-AzAccount

# Service principal login
Connect-AzAccount -ServicePrincipal -Credential $credential -Tenant $tenantId

# Managed identity login (from Azure VM)
Connect-AzAccount -Identity

# Check current context
Get-AzContext

# List available subscriptions
Get-AzSubscription
```

### Common Azure PowerShell Tasks

#### Resource Management
```powershell
# Create resource group
New-AzResourceGroup -Name "MyResourceGroup" -Location "East US"

# Get all resource groups
Get-AzResourceGroup

# Create storage account
$storageAccount = New-AzStorageAccount `
  -ResourceGroupName "MyResourceGroup" `
  -Name "mystorageaccount123" `
  -Location "East US" `
  -SkuName "Standard_LRS" `
  -Kind "StorageV2"

# Create virtual network
$virtualNetwork = New-AzVirtualNetwork `
  -ResourceGroupName "MyResourceGroup" `
  -Location "East US" `
  -Name "MyVNet" `
  -AddressPrefix "10.0.0.0/16"
```

#### Virtual Machine Management
```powershell
# Create VM configuration
$vmConfig = New-AzVMConfig -VMName "MyVM" -VMSize "Standard_B2s"

# Set operating system
$vmConfig = Set-AzVMOperatingSystem `
  -VM $vmConfig `
  -Windows `
  -ComputerName "MyVM" `
  -Credential $credential `
  -ProvisionVMAgent `
  -EnableAutoUpdate

# Set VM image
$vmConfig = Set-AzVMSourceImage `
  -VM $vmConfig `
  -PublisherName "MicrosoftWindowsServer" `
  -Offer "WindowsServer" `
  -Skus "2019-Datacenter" `
  -Version "latest"

# Create the VM
New-AzVM -ResourceGroupName "MyResourceGroup" -Location "East US" -VM $vmConfig
```

#### Scripting and Automation
```powershell
# Script to create multiple VMs
param(
    [Parameter(Mandatory=$true)]
    [string]$ResourceGroupName,
    
    [Parameter(Mandatory=$true)]
    [int]$VMCount,
    
    [Parameter(Mandatory=$true)]
    [string]$VMNamePrefix
)

for ($i = 1; $i -le $VMCount; $i++) {
    $vmName = "$VMNamePrefix$i"
    
    Write-Output "Creating VM: $vmName"
    
    New-AzVM `
        -ResourceGroupName $ResourceGroupName `
        -Name $vmName `
        -Location "East US" `
        -VirtualNetworkName "MyVNet" `
        -SubnetName "MySubnet" `
        -SecurityGroupName "MyNSG" `
        -Image "Win2019Datacenter" `
        -Size "Standard_B2s"
}
```

```bash
# Script to deploy web app infrastructure

echo "Creating resource group..."

  --name $APP_SERVICE_PLAN \
  --resource-group $RESOURCE_GROUP \

  --resource-group $RESOURCE_GROUP \
  --plan $APP_SERVICE_PLAN \
  --name $WEB_APP_NAME \
  --runtime "NODE|14-lts"

echo "Web app URL: https://$WEB_APP_NAME.azurewebsites.net"
```

## Azure Resource Manager Templates (ARM Templates)

### Definition
JSON files that define the infrastructure and configuration for Azure resources using declarative syntax.

### Template Structure
```json
{
  "$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
  "contentVersion": "1.0.0.0",
  "parameters": {
    // Input parameters
  },
  "variables": {
    // Internal variables
  },
  "functions": [
    // User-defined functions
  ],
  "resources": [
    // Azure resources to deploy
  ],
  "outputs": {
    // Return values
  }
}
```

### Template Components

#### Parameters
```json
{
  "parameters": {
    "storageAccountName": {
      "type": "string",
      "minLength": 3,
      "maxLength": 24,
      "metadata": {
        "description": "Name for the storage account"
      }
    },
    "storageAccountType": {
      "type": "string",
      "defaultValue": "Standard_LRS",
      "allowedValues": [
        "Standard_LRS",
        "Standard_GRS", 
        "Standard_ZRS"
      ]
    },
    "location": {
      "type": "string",
      "defaultValue": "[resourceGroup().location]"
    }
  }
}
```

#### Variables
```json
{
  "variables": {
    "storageAccountName": "[toLower(parameters('storageAccountName'))]",
    "containerName": "logs",
    "resourceTags": {
      "Environment": "[parameters('environment')]",
      "Project": "[parameters('projectName')]",
      "Owner": "[parameters('ownerEmail')]"
    }
  }
}
```

#### Resources
```json
{
  "resources": [
    {
      "type": "Microsoft.Storage/storageAccounts",
      "apiVersion": "2021-04-01",
      "name": "[variables('storageAccountName')]",
      "location": "[parameters('location')]",
      "tags": "[variables('resourceTags')]",
      "sku": {
        "name": "[parameters('storageAccountType')]"
      },
      "kind": "StorageV2",
      "properties": {
        "supportsHttpsTrafficOnly": true,
        "encryption": {
          "services": {
            "blob": {
              "enabled": true
            }
          },
          "keySource": "Microsoft.Storage"
        }
      }
    }
  ]
}
```

### Complete ARM Template Example
```json
{
  "$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
  "contentVersion": "1.0.0.0",
  "parameters": {
    "webAppName": {
      "type": "string",
      "metadata": {
        "description": "Name of the web app"
      }
    },
    "environment": {
      "type": "string",
      "defaultValue": "dev",
      "allowedValues": ["dev", "test", "prod"]
    }
  },
  "variables": {
    "appServicePlanName": "[concat(parameters('webAppName'), '-plan')]",
    "skuName": "[if(equals(parameters('environment'), 'prod'), 'S1', 'B1')]"
  },
  "resources": [
    {
      "type": "Microsoft.Web/serverfarms",
      "apiVersion": "2021-02-01",
      "name": "[variables('appServicePlanName')]",
      "location": "[resourceGroup().location]",
      "sku": {
        "name": "[variables('skuName')]"
      },
      "properties": {
        "reserved": true
      }
    },
    {
      "type": "Microsoft.Web/sites",
      "apiVersion": "2021-02-01",
      "name": "[parameters('webAppName')]",
      "location": "[resourceGroup().location]",
      "dependsOn": [
        "[resourceId('Microsoft.Web/serverfarms', variables('appServicePlanName'))]"
      ],
      "properties": {
        "serverFarmId": "[resourceId('Microsoft.Web/serverfarms', variables('appServicePlanName'))]",
        "siteConfig": {
          "linuxFxVersion": "NODE|14-lts"
        }
      }
    }
  ],
  "outputs": {
    "webAppUrl": {
      "type": "string",
      "value": "[concat('https://', reference(parameters('webAppName')).defaultHostName)]"
    }
  }
}
```

### Template Deployment

#### Using Azure CLI
```bash
# Deploy template
az deployment group create \
  --resource-group MyResourceGroup \
  --template-file template.json \
  --parameters webAppName=mywebapp environment=prod

# Deploy with parameter file
az deployment group create \
  --resource-group MyResourceGroup \
  --template-file template.json \
  --parameters @parameters.json

# Validate template before deployment
az deployment group validate \
  --resource-group MyResourceGroup \
  --template-file template.json \
  --parameters webAppName=mywebapp
```

#### Using Azure PowerShell
```powershell
# Deploy template
New-AzResourceGroupDeployment `
  -ResourceGroupName "MyResourceGroup" `
  -TemplateFile "template.json" `
  -webAppName "mywebapp" `
  -environment "prod"

# Deploy with parameter file
New-AzResourceGroupDeployment `
  -ResourceGroupName "MyResourceGroup" `
  -TemplateFile "template.json" `
  -TemplateParameterFile "parameters.json"

# Test template deployment
Test-AzResourceGroupDeployment `
  -ResourceGroupName "MyResourceGroup" `
  -TemplateFile "template.json" `
  -webAppName "mywebapp"
```

## Bicep

### Definition
Domain-specific language (DSL) that uses declarative syntax to deploy Azure resources, providing a more readable alternative to ARM templates.

### Bicep Advantages
- **Simpler Syntax**: More concise and readable than JSON
- **Type Safety**: Strong typing and IntelliSense support
- **Modularity**: Reusable modules and better code organization
- **Tooling**: Better IDE support and debugging capabilities

### Bicep Syntax Examples

#### Basic Resource Definition
```bicep
param storageAccountName string
param location string = resourceGroup().location

resource storageAccount 'Microsoft.Storage/storageAccounts@2021-04-01' = {
  name: storageAccountName
  location: location
  sku: {
    name: 'Standard_LRS'
  }
  kind: 'StorageV2'
  properties: {
    supportsHttpsTrafficOnly: true
  }
}

output storageAccountId string = storageAccount.id
```

#### Web App with Dependencies
```bicep
param webAppName string
param environment string = 'dev'

var appServicePlanName = '${webAppName}-plan'
var skuName = environment == 'prod' ? 'S1' : 'B1'

resource appServicePlan 'Microsoft.Web/serverfarms@2021-02-01' = {
  name: appServicePlanName
  location: resourceGroup().location
  sku: {
    name: skuName
  }
  properties: {
    reserved: true
  }
}

resource webApp 'Microsoft.Web/sites@2021-02-01' = {
  name: webAppName
  location: resourceGroup().location
  properties: {
    serverFarmId: appServicePlan.id
    siteConfig: {
      linuxFxVersion: 'NODE|14-lts'
    }
  }
}

output webAppUrl string = 'https://${webApp.properties.defaultHostName}'
```

#### Bicep Modules
```bicep
// storage.bicep (module file)
param storageAccountName string
param location string = resourceGroup().location

resource storageAccount 'Microsoft.Storage/storageAccounts@2021-04-01' = {
  name: storageAccountName
  location: location
  sku: {
    name: 'Standard_LRS'
  }
  kind: 'StorageV2'
}

output storageAccountName string = storageAccount.name
output storageAccountId string = storageAccount.id

// main.bicep (using the module)
param projectName string
param environment string

module storage 'storage.bicep' = {
  name: 'storageDeployment'
  params: {
    storageAccountName: '${projectName}${environment}storage'
    location: resourceGroup().location
  }
}

output storageInfo object = {
  name: storage.outputs.storageAccountName
  id: storage.outputs.storageAccountId
}
```

### Bicep Deployment
```bash
# Install Bicep CLI
az bicep install

# Build Bicep to ARM template
az bicep build --file main.bicep

# Deploy Bicep file directly
az deployment group create \
  --resource-group MyResourceGroup \
  --template-file main.bicep \
  --parameters webAppName=mywebapp environment=prod

# Decompile ARM template to Bicep
az bicep decompile --file template.json
```

## Deployment Best Practices

### 1. Infrastructure as Code (IaC)
```
Benefits:
├── Version Control: Track infrastructure changes
├── Repeatability: Deploy identical environments
├── Documentation: Code serves as documentation
├── Testing: Validate infrastructure before deployment
└── Automation: Integrate with CI/CD pipelines
```

### 2. Environment Strategy
```
Environment Separation:
├── Development: Individual developer environments
├── Testing: Shared testing environment
├── Staging: Production-like environment
├── Production: Live customer-facing environment
└── DR: Disaster recovery environment
```

### 3. Deployment Patterns
```
Blue-Green Deployment:
├── Blue Environment: Current production
├── Green Environment: New version deployment  
├── Switch: Route traffic to green environment
└── Rollback: Quick switch back to blue if issues

Canary Deployment:
├── Small Percentage: Route 5% traffic to new version
├── Monitor: Check metrics and user feedback
├── Gradual Increase: Increase to 25%, 50%, 100%
└── Rollback: Quick rollback if issues detected
```
