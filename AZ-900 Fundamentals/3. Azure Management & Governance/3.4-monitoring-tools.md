# 3.4 Azure Monitoring Tools

## Azure Advisor

### Definition
Azure Advisor is a personalized cloud consultant that analyzes your resource configuration and usage telemetry, then provides recommendations to help optimize Azure deployments.

### Purpose
- **Proactive guidance**: Recommendations before problems occur
- **Best practices**: Follow Azure well-architected framework
- **Cost savings**: Identify optimization opportunities
- **Performance improvements**: Enhance application performance
- **Security enhancements**: Strengthen security posture

---

### Advisor Recommendation Categories

#### 1. Reliability (High Availability)

##### Purpose
Ensure continuity of business-critical applications.

##### Example Recommendations

**Enable Backup for Virtual Machines**
```
Issue: VM has no backup configured
Impact: Data loss risk if VM fails
Recommendation: Enable Azure Backup
Benefit: Protect against data loss
Potential downtime prevented: Hours to days
```

**Use Availability Zones**
```
Issue: VM deployed in single availability zone
Impact: Vulnerable to datacenter failure
Recommendation: Deploy across multiple availability zones
Benefit: 99.99% SLA instead of 99.9%
```

**Configure Application Gateway with Multiple Instances**
```
Issue: Single instance application gateway
Impact: Single point of failure
Recommendation: Deploy with minimum 2 instances
Benefit: High availability for web applications
```

**Add Redundancy to ExpressRoute Circuit**
```
Issue: Single ExpressRoute connection
Impact: Connectivity loss if circuit fails
Recommendation: Configure redundant circuit
Benefit: Maintain connectivity during failures
```

---

#### 2. Security

##### Purpose
Detect vulnerabilities and strengthen security posture.

##### Example Recommendations

**Enable Multi-Factor Authentication (MFA)**
```
Issue: Privileged accounts without MFA
Impact: Increased risk of account compromise
Recommendation: Require MFA for admin accounts
Benefit: Significantly reduced breach risk
Implementation: Azure AD Conditional Access
```

**Update to Latest OS Version**
```
Issue: VM running outdated OS version
Impact: Security vulnerabilities
Recommendation: Update to latest version
Benefit: Protection against known exploits
```

**Enable Disk Encryption**
```
Issue: VM disks not encrypted
Impact: Data exposure if disk compromised
Recommendation: Enable Azure Disk Encryption
Benefit: Data protected at rest
```

**Configure Network Security Groups**
```
Issue: Overly permissive NSG rules
Impact: Potential unauthorized access
Recommendation: Restrict to necessary ports/IPs
Benefit: Reduced attack surface
```

**Enable Advanced Threat Protection**
```
Issue: Storage account without ATP
Impact: Missed threat detection
Recommendation: Enable Microsoft Defender for Storage
Benefit: Real-time threat detection
```

---

#### 3. Performance

##### Purpose
Improve speed and responsiveness of applications.

##### Example Recommendations

**Improve Database Performance**
```
Issue: High DTU usage (>80%) on SQL Database
Impact: Slow query response times
Recommendation: Scale to higher tier or optimize queries
Benefit: Improved application performance
Estimated improvement: 30-50% faster queries
```

**Use Premium Storage for Production VMs**
```
Issue: Standard HDD for production VM
Impact: Slow disk operations
Recommendation: Upgrade to Premium SSD
Benefit: 10x faster IOPS
```

**Enable CDN for Static Content**
```
Issue: Serving static content from single region
Impact: High latency for distant users
Recommendation: Configure Azure CDN
Benefit: Reduced latency, improved user experience
```

**Resize Underutilized Virtual Machines**
```
Issue: Large VM with low CPU usage (<5%)
Impact: Wasted resources and cost
Recommendation: Downsize to smaller VM
Benefit: Better performance-to-cost ratio
```

#### 4. Cost

##### Purpose
Reduce spending without sacrificing functionality.

##### Example Recommendations

**Right-Size Virtual Machines**
```
Issue: VM oversized for workload
Current: Standard_D4s_v3 (4 vCPU, 16 GB) - $140/month
CPU usage: Average 5%
Recommendation: Standard_D2s_v3 (2 vCPU, 8 GB) - $70/month
Potential savings: $70/month ($840/year)
```

**Purchase Reserved Instances**
```
Issue: Consistent VM usage with pay-as-you-go pricing
Current cost: $500/month
Usage pattern: 24/7 for 12+ months
Recommendation: 1-year reserved instance
Savings: $200/month ($2,400/year, 40% discount)
```

**Delete Unattached Disks**
```
Issue: Managed disks not attached to any VM
Current cost: $20/month for unused storage
Recommendation: Delete unused disks
Savings: $20/month ($240/year)
```

**Shutdown Non-Production VMs**
```
Issue: Dev/Test VMs running 24/7
Current cost: $300/month
Usage: Only needed during business hours
Recommendation: Auto-shutdown schedule (6pm-8am, weekends)
Savings: $180/month ($2,160/year, 60% reduction)
```

**Move to Lower-Cost Storage Tier**
```
Issue: Data in Hot storage tier, accessed rarely
Current: Hot tier - $100/month
Access pattern: Once per quarter
Recommendation: Move to Cool or Archive tier
Savings: $50/month ($600/year, 50% reduction)
```

## Azure Service Health

### Definition
Azure Service Health provides personalized alerts and guidance when Azure service issues affect your resources, including planned maintenance and health advisories.

### Purpose
- **Service awareness**: Know about Azure platform issues
- **Impact assessment**: Understand if issues affect your resources
- **Planned maintenance**: Prepare for scheduled updates
- **Historical tracking**: Review past incidents

---

### Service Health Components

#### 1. Service Issues

##### Definition
Current problems affecting Azure services that impact your deployed resources.

##### Information Provided
- **Issue description**: What's happening
- **Affected services**: Which Azure services
- **Affected regions**: Geographic scope
- **Impact to you**: Your affected resources
- **Status updates**: Real-time progress
- **Root cause**: After resolution
- **Next steps**: Recommended actions

##### Example Service Issue
```
Title: Virtual Machines - Connectivity Issues - West Europe

Status: Investigating

Description:
We are investigating connectivity issues affecting 
Virtual Machines in West Europe region.

Impact to your resources:
- 3 VMs affected in West Europe
- Resource Group: Production-RG

Last update: 2 minutes ago
Next update: In 15 minutes or sooner

Recommended actions:
- Monitor VM status
- Prepare failover if available
- Check Service Health for updates
```

##### Issue Lifecycle
```
1. Investigating → Initial detection
2. Identified → Root cause found
3. Mitigating → Fix in progress
4. Resolved → Service restored
5. Post-incident review → RCA published
```

---

#### 2. Planned Maintenance

##### Definition
Scheduled Azure platform updates that may affect your resources.

##### Notification Timeline
```
Typical notice:
- 30+ days advance notice for most maintenance
- 7-14 days for urgent security updates
- Reminder notifications before maintenance window
```

##### Maintenance Categories

**Platform Maintenance**
```
Type: Azure infrastructure updates
Impact: Minimal or no impact
Examples:
- Host OS patches
- Network infrastructure updates
- Storage improvements

Typical downtime: None (live migration)
```

**VM Reboot Required**
```
Type: Guest OS or critical updates
Impact: Brief downtime during reboot
Notice: 30+ days
Options: 
- Self-service maintenance (choose timing)
- Automatic maintenance (scheduled window)

Typical downtime: 1-2 minutes
```

**Redeploy Required**
```
Type: Major infrastructure changes
Impact: Longer downtime
Notice: 60+ days
Action: Move to new infrastructure

Typical downtime: 15-30 minutes
```

##### Example Planned Maintenance
```
Title: Virtual Machines - Host Maintenance - East US

Scheduled: January 15, 2025, 02:00-06:00 UTC

Affected resources:
- 5 VMs in East US
- Resource Groups: Web-RG, App-RG

Impact: Brief VM restart (1-2 minutes)

Options:
1. Self-service maintenance (available now)
   - Choose your own timing before Jan 15
   
2. Automatic maintenance (default)
   - Azure performs maintenance Jan 15 02:00 UTC

Recommendation: 
Schedule self-service maintenance during 
your maintenance window to control timing.
```

### Service Health vs Azure Status

#### Azure Status Page
- **URL**: https://status.azure.com
- **Scope**: All Azure services, all regions
- **View**: Public, global status
- **Use**: General Azure health information

#### Service Health (in Portal)
- **Location**: Azure Portal → Service Health
- **Scope**: Your specific resources and subscriptions
- **View**: Personalized to your deployments
- **Use**: Issues affecting YOUR resources specifically

#### Comparison
```
Question: "Is Azure down globally?"
Answer: Check Azure Status page

Question: "Are MY resources affected?"
Answer: Check Service Health in portal

Service Health = Personalized Azure Status
```

## Azure Monitor

### Definition
Azure Monitor is a comprehensive solution for collecting, analyzing, and acting on telemetry from cloud and on-premises environments to maximize performance and availability.

### Purpose
- **Observability**: Understand application and infrastructure behavior
- **Performance**: Identify and resolve performance issues
- **Availability**: Detect and respond to failures
- **Capacity planning**: Understand usage trends
- **Troubleshooting**: Diagnose and resolve issues

---

### Azure Monitor Components

#### 1. Metrics

##### Definition
Numerical time-series data collected at regular intervals, describing performance and health.

##### Characteristics
- **Lightweight**: Low overhead
- **Near real-time**: 1-minute granularity
- **Retention**: 93 days
- **Aggregations**: Average, min, max, sum, count

##### Example Metrics

**Virtual Machine Metrics**
```
- CPU percentage
- Network in/out
- Disk read/write bytes
- Disk operations/sec
- Available memory
```

**Storage Account Metrics**
```
- Transactions
- Ingress/egress (bytes)
- Availability
- Success/failure rates
- End-to-end latency
```

**SQL Database Metrics**
```
- DTU/CPU percentage
- Database size
- Active connections
- Deadlocks
- Blocked queries
```

##### Viewing Metrics
```
Azure Portal:
1. Navigate to resource
2. Click "Metrics" in left menu
3. Select metric to chart
4. Choose time range
5. Apply aggregation (avg, max, min)
6. Add to dashboard

Result: Visual chart showing metric over time
```

#### 3. Kusto Query Language (KQL)

##### Definition
Query language for analyzing log data in Azure Monitor.

##### Basic Query Structure
```kusto
TableName
| where TimeGenerated > ago(1h)
| where ResultType == "Error"
| summarize count() by Computer
| top 10 by count_
```

##### Common Query Examples

**Find Errors in Last Hour**
```kusto
AzureActivity
| where TimeGenerated > ago(1h)
| where Level == "Error"
| project TimeGenerated, Caller, ResourceGroup, OperationName
```

**Virtual Machine Performance**
```kusto
Perf
| where ObjectName == "Processor" and CounterName == "% Processor Time"
| where Computer == "MyVM"
| summarize avg(CounterValue) by bin(TimeGenerated, 5m)
| render timechart
```

**Failed Login Attempts**
```kusto
SigninLogs
| where ResultType != 0  // 0 = success
| summarize FailedAttempts = count() by UserPrincipalName
| order by FailedAttempts desc
```

**Storage Account Transactions**
```kusto
StorageBlobLogs
| where StatusText != "Success"
| summarize count() by StatusText, AccountName
| render piechart
```

#### 4. Alerts

##### Definition
Automated notifications when specific conditions are met in metrics or logs.

##### Alert Components

**Alert Rule**
```
Components:
1. Target resource (what to monitor)
2. Condition (when to trigger)
3. Action group (what to do)
4. Alert details (severity, description)
```

##### Alert Types

**Metric Alerts**
```
Example: High CPU Alert

Target: Virtual Machine "WebServer01"
Condition: CPU > 80%
Duration: 5 minutes
Action: Email ops-team@company.com
Severity: Warning

Trigger: When CPU exceeds 80% for 5 consecutive minutes
```

**Log Query Alerts**
```
Example: Failed Login Alert

Query:
SigninLogs
| where ResultType != 0
| summarize FailedAttempts = count() by UserPrincipalName
| where FailedAttempts > 5

Frequency: Every 5 minutes
Condition: Query returns results
Action: Email security-team@company.com
Severity: Critical
```

**Activity Log Alerts**
```
Example: Resource Deletion Alert

Target: Production subscription
Condition: 
  - Operation: Delete resource
  - Resource type: Virtual Machine
Action: SMS to on-call team
Severity: Critical

Trigger: Anytime VM deleted in Production
```

### Azure Monitor Best Practices

#### 1. Enable Diagnostics Early
```
Best practice: Enable during resource creation
Benefit: Historical data available for troubleshooting
Default: Many resources don't enable diagnostics automatically
```

#### 2. Use Log Analytics Workspace
```
Centralize logs from multiple sources:
- Azure resources
- On-premises servers
- Applications
- Security logs

Benefit: Cross-resource queries and correlation
```

#### 3. Create Meaningful Alerts
```
Good alerts:
✅ Actionable (clear action needed)
✅ Appropriate threshold (not too sensitive)
✅ Right severity (matches impact)
✅ Clear description (what's wrong, what to do)

Bad alerts:
❌ Too sensitive (alert fatigue)
❌ Not actionable (FYI only)
❌ No context (can't determine impact)
```

#### 4. Build Team Dashboards
```
Create role-specific dashboards:
- Operations: Resource health, performance
- Development: Application errors, performance
- Management: Costs, capacity, SLAs
- Security: Failed logins, policy violations

Share dashboards with teams
```

#### 5. Regular Review and Tuning
```
Monthly:
- Review alert frequency
- Adjust thresholds if needed
- Remove or modify noisy alerts
- Update dashboards with new metrics
- Clean up old queries and workbooks
```
